会话创建后，您可以使用以下操作来读取、更新、归档或删除它。有关创建会话并向其发送任务的信息，请参阅[启动会话](/docs/zh/sessions)。

<Note>
  各资源的 Beta 要求不同，请参阅[版本与 Beta 功能](/docs/zh/api/versioning-beta)，并确认 SDK 向 OMA 发送了所需参数。
</Note>

## 会话状态

会话会经历以下状态。有关会话生命周期的信息，请参阅[启动会话](/docs/zh/sessions)。

| 状态             | 描述                                                                  |
| -------------- | ------------------------------------------------------------------- |
| `idle`         | 智能体正在等待输入，包括用户消息或工具确认。未设置 `initial_events` 创建的会话初始状态为 `idle`。       |
| `running`      | 智能体正在主动执行。                                                          |
| `rescheduling` | 发生了暂时性错误，正在自动重试。                                                    |
| `terminated`   | 会话已结束，原因可能是发生了不可恢复的错误，或会话已被归档。完成工作的会话会进入 `idle` 状态，而非 `terminated`。 |

## 更新智能体配置

您可以在会话进行中更新会话的 `agent.tools` 和 `agent.mcp_servers`（包括权限策略），而无需创建新的智能体版本。更新仅作用于当前会话，不会传播回底层智能体。

会话创建后，只有智能体的 `tools` 和 `mcp_servers` 可以更改。如需使用与智能体不同的 `model`、`system` 或 `skills` 值运行会话，请在创建会话时使用[智能体配置覆盖](/docs/zh/sessions#override-agent-configuration-for-a-session)。智能体的模型配置在会话进行中无法更改。智能体配置的 `system` 字段在会话的整个生命周期内是固定的。在支持此功能的模型上，您仍可以通过发送 [`system.message` 事件](/docs/zh/events-and-streaming#sending-system-messages)在会话进行中追加系统级指导。

`tools` 或 `mcp_servers` 更新的语义是完全替换：提供的数组即为新值。如需保留现有条目，请先 `GET` 会话，修改数组，然后 `POST` 回去。

会话必须处于 `idle` 状态才能更新智能体。如果您需要在智能体运行时更新它，请先[中断](/docs/zh/events-and-streaming#integrating-events)会话。

## 更新会话预算

[创建时设置了预算](/docs/zh/sessions#set-a-session-budget)的会话接受两种预算更新：使用新的 `max_list_cost` 替换上限，以及通过将 `budget` 设置为 `null` 来移除上限。更新会清除触顶标记；请检查会话状态并按需发送新消息继续工作。替换的上限可以高于或低于当前上限，但必须严格大于会话已消耗的标价成本（list cost）；移除操作是单向的：只有当前已设置 `budget` 的会话才接受非 null 的 `budget`，因此您无法重新添加已移除的预算，也无法为创建时未设置预算的会话添加预算。有关请求示例、错误行为以及哪些内容计入标价成本，请参阅[会话预算](/docs/zh/budgets#resume-a-session-at-its-budget)。

## 列出会话

`GET /v1/sessions` 返回 `data` 和 `next_page`。使用 `limit` 控制每页数量；存在下一页时，将 `next_page` 原样作为下次请求的 `page` 参数。没有更多结果时该字段为 `null`。接口不返回 `prev_page`；如需回看上一页，请在客户端保留先前的结果或请求游标。遍历期间建议保持排序和筛选条件不变。`order` 按创建时间排序，默认 `desc`。

```bash
first_page=$(curl -sS --fail-with-body --get "$OMA_BASE_URL/v1/sessions" \
  -H "x-api-key: $OMA_API_KEY" \
  --data-urlencode 'limit=20')
printf '%s\n' "$first_page" | jq '.data'
next_page=$(printf '%s\n' "$first_page" | jq -r '.next_page // empty')
if [ -n "$next_page" ]; then
  curl -sS --fail-with-body --get "$OMA_BASE_URL/v1/sessions" \
    -H "x-api-key: $OMA_API_KEY" \
    --data-urlencode 'limit=20' --data-urlencode "page=$next_page"
fi
```

设置 `OMA_BASE_URL` 和 `OMA_API_KEY` 的方法见[认证](/docs/zh/api/authentication)。不同资源的分页参数可能不同，详见[分页](/docs/zh/api/pagination)。

## 归档会话

归档会话可防止发送新事件，同时保留其历史记录。正在执行的任务可能阻止归档；请先发送[中断事件](/docs/zh/events-and-streaming)并等待会话进入可归档状态，再重试。

<CodeGroup defaultLanguage="CLI">
  ```bash cURL
  curl -fsSL -X POST "http://localhost:38080/v1/sessions/$SESSION_ID/archive" \
    -H "x-api-key: $OMA_API_KEY" \
    -H "anthropic-version: 2023-06-01" \
    -H "anthropic-beta: managed-agents-2026-04-01"
  ```

  ```bash CLI
  ant beta:sessions archive \
    --session-id "$SESSION_ID"
  ```

## 删除会话

删除会话后，相关记录和事件不再可访问，沙箱等资源会进入清理流程。正在执行的任务可能阻止删除；请先发送[中断事件](/docs/zh/events-and-streaming)，等待会话进入可删除状态后重试。物理资源清理可能异步完成。

记忆存储、密钥库、技能、环境和智能体是独立的资源，不受会话删除的影响。您通过文件 API 上传的文件也不受影响，但会话本身生成的文件作用域限定于该会话，会随其文件系统一起被永久删除。请在删除会话之前下载您需要保留的任何内容。
