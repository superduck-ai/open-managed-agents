# 组织与工作区成员管理（#336）

本功能基于 main，复用已合并的 #339（PR #346）通用权限及成员事务、#338（PR #347）组织加入与切换上下文。组织角色为 User/Admin，工作区角色为 Workspace User/Workspace Admin，与 main 的角色简化合同一致。

## 产品与权限边界

组织成员是加入组织的人；工作区成员表示这些人在某个空间的有效访问权限。Console API 是网页使用的会话认证接口，不是一种成员身份。对外 Admin API 与 Console API 应共享领域规则。

组织和工作区用户均可只读查看所在组织及可访问工作区的成员目录；普通用户不请求邀请及候选目录，不显示角色编辑、添加或移除入口。Default 保留跳转组织成员目录的入口。组织 Admin 管理组织邀请、角色和移除操作。前端只根据当前组织的角色显示入口，其他组织的 Admin 身份不能提供权限。后端重新查询操作者的有效组织成员关系；成员修改事务内再次校验角色，不能仅依赖会话中的历史角色。

组织必须保留至少一名有效 Admin。Console 和 Admin API 的删除、降级共用组织行锁和管理员计数，最后一名管理员变更返回 409。移除组织成员时，在同一事务中软删除组织关系和该组织下的显式工作区关系；其他组织关系、工作区团队资源和 Key 保留。重复移除返回 404。

```mermaid

  UI->>API: 确认移除（会话、CSRF、组织范围）

  TX->>TX: 检查最后管理员与操作者最新角色
```

普通工作区按拆分后的 #346 基线执行：组织 Admin 继承 Workspace Admin，不能编辑或移除；组织 User 通过显式工作区角色加入，可以修改角色或移除显式成员。Default 的权限全部来自组织角色，历史显式关系不参与计算，不提供独立成员管理操作。

## 工作区 Console 合同

`/api/console/organizations/{organizationUuid}` 路由组统一执行会话 CSRF 校验。POST、PATCH、DELETE 等变更请求必须携带当前会话的 `X-CSRF-Token`；缺失、无效或其他会话的 token 返回 403，GET、HEAD、OPTIONS 不要求 token。成员授权与事务内角色复查仍独立执行。

全局会话中间件不对工作区成员路由要求组织管理权限；目录、候选和写入接口在资源层解析 URL 中的目标工作区；目录校验工作区访问权限，候选与写入校验成员管理权限，写入接口在查询目标组织成员前完成该校验，并在事务内再次复查权限。无成员管理权限时，无论目标成员是否存在，写入统一返回 403 `workspace_access_denied`，不泄露组织成员身份。组织普通成员获授 Workspace Admin 后可以管理该空间成员，但不能管理组织或未授权的其他空间，且不能依赖会话当前工作区的角色替代目标空间校验。

路径前缀为 `/api/console/organizations/{organizationUuid}/workspaces/{workspaceId}`。

| 方法与路径 | 合同 |
| --- | --- |
| GET `/members` | 返回 `workspace_id`、`is_default`、`can_manage_members`、`members` |
| GET `/member-candidates` | 返回同组织内尚可添加的成员，字段为 `user_id`、`name`、`email` |
| POST `/members` | 以 `user_id`、`workspace_role` 添加显式成员 |
| POST `/members/{userId}` | 更新显式 `workspace_role` |
| DELETE `/members/{userId}` | 移除显式成员 |

每个成员返回身份、姓名、邮箱、组织角色、有效工作区角色、角色来源及 `can_edit`、`can_remove`。界面消费服务端权限，不自行复制继承算法。目录与候选查询复用 `ListWorkspaceMemberFacts`；添加、改角色和移除统一走 `workspaceaccess.ChangeMember`（组织成员行锁 → 工作区锁 → 操作者授权 → Default 保护 → 显式角色规则）。组织 Admin 的继承访问不可编辑或移除；User 显式成员可编辑和移除；候选列表排除 Admin 与已有显式成员。添加与更新仅提供 Workspace User、Workspace Admin。

组织 Admin 查询 Default 成员目录时，`can_manage_members` 和所有成员的 `can_edit`、`can_remove` 均为 false。Default 的候选查询与成员写操作统一返回 409 `default_workspace_protected`，成员管理应转到组织设置。

## 组织成员 Console 合同

组织成员写路径（改角色、移除）挂 `requireConsoleOrganizationAdmin` 中间件，任何登录成员包括其他组织管理员都不可操作。DB 层 `withOrganizationMemberChange` 在组织行锁事务内校验操作者最新角色与最后管理员计数；Admin API 的 `UpdateAdminUserRole`/`DeleteAdminUser` 与 Console 共用同一保护。移除最后管理员返回 409 `last_organization_admin`，重复移除返回 404，非管理员返回 403。

## 页面与 CMA 对照

组织成员页提供计数、权限说明、搜索、角色筛选、行内角色选择和更多操作菜单；普通工作区成员页额外支持姓名/邮箱/角色排序。没有查看权限时显示明确提示：成员可以只读查看目录，管理操作仍限管理员，且不请求成员目录；服务器返回 403 或当前权限撤销时隐藏缓存目录。组织右上入口为 Invite，工作区为 Add to Workspace。移除使用确认弹窗，提交期间禁用操作，后端失败保留弹窗和原因。切换组织或工作区后重置弹窗状态。

组织成员页首次加载期间，只要成员或管理员的待处理邀请查询仍在等待结果，就显示骨架并隐藏人数计数；因离线暂停的查询也属于等待结果。只有所需目录均已成功返回且筛选结果为空时才显示空列表，不能把未加载的数据当成零成员。恢复网络后继续查询并展示真实目录；已有完整缓存时仍可展示缓存内容。

工作区成员移除确认显示当前工作区名称，明确只移除该空间的显式成员关系。工作区设置的归档筛选单独请求 `include_archived=true`，导航选择器仍只使用活动工作区；归档记录不提供编辑或再次归档入口。

归档弹窗打开和关闭时清空上次操作错误；失败后重新打开同一工作区或其他工作区时，不显示先前的错误。

移除成员、归档工作区和撤销邀请的确认弹窗在退出过渡中保留原目标及错误展示，避免父页面清空选择后出现空邮箱或空工作区名称。下一次打开使用新目标和当前错误状态。取消通过 Base UI Close 处理，撤销邀请不得重复绑定清空回调；处理中禁用操作并拒绝 Escape 关闭。

邀请表单取消和成功退出时，邮箱、角色与校验状态在 Base UI 退出完成后重置，成功回调及目录更新立即执行。提交中关闭和取消禁用，Escape 不关闭；失败保留草稿。工作区添加成员保留受控 open 合同，用户关闭时等待退出完成再通知父页面卸载；提交中禁用关闭，重新打开仍可正常选择候选。

已观察 `platform.claude.com` 组织成员和普通工作区成员页的布局、权限说明与操作入口。真实 CMA 的移除操作未执行；添加弹窗因无可添加成员未能观察。本地验收需要逐项对照布局、筛选、表格、角色变更、添加和移除流程，不能将页面观察视为写操作验收。
