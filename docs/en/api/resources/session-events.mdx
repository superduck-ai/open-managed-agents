---
title: "Session events and streams"
description: "Send input, page through history, and subscribe to session or thread SSE."
---

Every path requires `?beta=true`.

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` / `POST` | `/v1/sessions/{id}/events` | List history / send client events |
| `GET` | `/v1/sessions/{id}/events/stream` | Primary SSE stream |
| `GET` | `/v1/sessions/{id}/threads/{thread_id}/events` | Thread history |
| `GET` | `/v1/sessions/{id}/threads/{thread_id}/stream` | Thread SSE |

History supports `limit`, `page`, `order`, `types`/`types[]`, and `created_at[gt|gte|lt|lte]`. Time filters always compare creation time and can include queued inputs. `event_start` and `event_delta` appear only in live streams.

History is ordered by `processed_at`, with database insertion order breaking ties. The default is `order=desc`; explicitly request `order=asc` for chronological history. Queued inputs have `processed_at=null` and appear last in ascending order or first in descending order.

`page` is an opaque server-issued cursor; pass it back unchanged. The current format uses processing time and the public event ID. Older cursors using creation time and an internal UUID are incompatible: discard them and restart from the first page after upgrading. Pagination is not a snapshot: Worker ACKs move queued inputs into the processed timeline, so concurrent pagination can repeat or omit events. Deduplicate by event ID, use SSE for live delivery, and reload history when a complete view is needed.

```json
{
  "events": [
    {
      "type": "user.message",
      "content": [{ "type": "text", "text": "Run the focused test suite." }]
    }
  ]
}
```

Tool confirmation uses `user.tool_confirmation`; custom tool output uses `user.custom_tool_result`. Both reference the original call ID, and child-thread replies include `session_thread_id`.
