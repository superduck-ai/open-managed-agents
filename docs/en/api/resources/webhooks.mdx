---
title: "Webhooks"
description: "Register endpoints, select events, and rotate signing secrets."
---

This page describes the current OMA contract. The [official Claude AWS IAM mapping](https://platform.claude.com/docs/en/api/claude-platform-on-aws-iam-actions) confirms these management routes, but does not define their full request/response schema. Field-level compatibility and the beta header below have not been independently confirmed against Claude.

Every request requires `anthropic-beta: webhooks-2026-03-01`.

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` / `GET` | `/v1/webhooks` | Create / list |
| `GET` / `POST` / `DELETE` | `/v1/webhooks/{id}` | Retrieve / update / delete |
| `POST` | `/v1/webhooks/{id}/regenerate_signing_secret` | Rotate signing secret |

```json
{
  "url": "https://hooks.example.com/oma",
  "name": "production-events",
  "description": "Session and vault lifecycle",
  "enabled_events": ["session.status_idled", "session.updated"]
}
```

`url` and a non-empty `enabled_events` array are required. `name` and `description` may be omitted or set to an empty string; `null` and other non-string values are rejected. The existing limits are 2048 bytes for URL/description and 255 bytes for name. POST updates accept `url`, `name`, `description`, `enabled_events`, and `status` (`enabled` or `disabled`); omitted fields are preserved.

URLs require HTTPS on port 443 without credentials or fragments. Private IP literals and localhost are rejected unless `webhook.allow_insecure` enables local HTTP targets. This is not complete DNS-based SSRF protection. Events must be in the server allowlist; the Console currently offers 21 types, including `session.updated` and `session.deleted`, and starts with none selected.

Endpoints belong to the authenticated workspace. List returns `{ "data": [...], "next_page": null }`; Console ID search and sorting operate on this returned collection. The Console supports editing, enabling/disabling, deleting, and rotating secrets. Failed operations retain the form or confirmation and show the server error.

Create returns `signing_secret` once; rotation returns a replacement. List, retrieve, and update never expose it. The Console keeps it only in the one-time dialog state. Consumers verify the Standard Webhooks `webhook-id`, `webhook-timestamp`, and `webhook-signature` headers with the official SDK and handle duplicate delivery idempotently.

The delivery worker starts by default, including for database subscriptions without a global endpoint/key. Set `webhook.worker_enabled: false` to disable delivery on this instance. The API allowlist and Console both use the same 21 canonical event types; legacy `session.error` and `session.thread_status_*` subscriptions are rejected.

Sessions created by manual or scheduled Deployment runs emit `session.status_idled` after the transaction commits. Creating the primary thread does not emit child-thread events, and defining an initial outcome does not emit `session.outcome_evaluation_ended`; that event follows an actual evaluation-end event. Failed runs and duplicate scheduled occurrences do not create new notifications. Two independent manual runs notify separately. Deployment resource events are not added by this behavior.

Environment subscriptions support `environment.created`, `environment.updated`, `environment.archived`, and `environment.deleted`. Creation refers to the environment record, not sandbox readiness. Updates notify only when persisted attributes change; no-op updates and repeated archives preserve timestamps and emit nothing. Deletion notifies after the existing transaction succeeds, including deletion of an archived environment; active work still blocks deletion. Work/heartbeat/sandbox state changes and SDK fixture responses do not emit these resource events. Payloads contain identifiers only. The global compatibility defaults and retry policy are unchanged. Resource commits and notification enqueueing remain separate: a crash or enqueue failure can lose a notification.
