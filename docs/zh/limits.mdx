---
title: "限制与成本控制"
description: "了解当前 OMA 限制，以及在没有会话预算 API 时如何控制资源。"
---

OMA 当前不实现 `budget` 字段和标价成本计量。自托管部署者需要在多个层级组合限制。

## 已实现限制

- 智能体：最多 20 个 MCP 服务器、20 个技能、128 个工具相关条目
- Multi-agent roster：1 到 20 个不同智能体
- 会话/部署 resources：最多 500 个
- Metadata：通常最多 16 个字符串键值
- 文件：单文件和工作区容量由 YAML 配置
- 软件包清单：1 MiB；环境 package 安装有独立超时
- 消息请求：OMA 网关请求体上限 32 MiB
- Batch：请求数、body、保留时间和 worker 并发可配置

## 成本控制层

1. 在上游模型账号配置支出和速率限制。
2. 用 `anthropic_upstream.model_mappings` 限定可用逻辑模型。
3. 设置沙箱 CPU、内存、磁盘和生命周期。
4. 设置 `environment_runner.concurrency` 与 provider 配额。
5. 为自动部署配置告警、pause 和人工复核。
6. 监控会话 `usage`、`stats`、模型请求 span 和上游账单。

## 达到外部限制时

上游 429/5xx、沙箱超时或队列积压应被当作可观察状态，而不是无界重试。客户端使用指数退避和抖动，并设置整体业务 deadline。需要继续的任务应读取已有会话和事件，避免重复创建产生双重成本。
