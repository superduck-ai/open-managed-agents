启用子智能体后，父智能体可以将任务委派出去。子智能体在同一个会话的独立线程中执行，并将结果返回父线程。你可以在会话中查看线程及其事件。

## 在控制台配置

1. 在工作区先创建需要复用的子智能体，并配置模型、提示词和技能。
2. 创建或编辑父智能体，在多智能体设置中启用**子智能体**。
3. 选择是否允许临时创建子智能体；需要固定专家时，添加工作区中的预定义智能体。
4. 保存父智能体，使用它[启动会话](/docs/zh/sessions)，在会话中查看子线程。

如果关闭临时子智能体，必须至少添加一个预定义智能体。一个名单最多包含 20 个不同的智能体。被引用的其他智能体不能再配置多智能体委派。

## 通过 API 配置

创建或更新父智能体时，可以在 `multiagent` 中配置子智能体。下例中的 `agent_example` 应替换为同一工作区内的智能体 ID：

```json
{
  "multiagent": {
    "type": "multiagent_20261001",
    "subagents": {
      "type": "enabled",
      "inline_agents": { "type": "disabled" },
      "predefined_agents": [{ "type": "agent", "id": "agent_example" }]
    },
    "workflows": { "type": "disabled" },
    "advisor": { "type": "disabled" }
  }
}
```

`inline_agents` 允许或禁止会话中临时定义子智能体。`predefined_agents` 中可以提供 `version` 指定版本；省略时，保存父智能体会固定该子智能体当时的最新版本。后续更新子智能体不会自动改变已保存的引用：要使用新版本，请更新父智能体的名单。

创建会话时，OMA 将固定版本展开为会话的配置快照。父智能体以后更新不会改变已有会话的快照。已有 `coordinator` 类型的配置仍可使用。

<Note>
`workflows` 和 `advisor` 字段用于兼容配置格式；当前 OMA 不执行工作流调度或顾问咨询。示例中显式关闭这两项。
</Note>

## 查看线程和处理工具请求

父线程委派任务后，子智能体在线程中产生自己的消息和工具事件。可以通过会话详情查看线程，也可以使用[会话事件流](/docs/zh/events-and-streaming)读取事件。工具需要确认时，按请求中的线程和工具调用信息处理，避免将不同线程的请求混淆。

预定义子智能体使用各自智能体配置中的工具权限；inline 子智能体继承会话的工具配置。MCP 连接和沙箱网络还受运行路径与环境配置影响。请先在被引用的每个子智能体上配置权限，并为会话配置网络访问，再验证委派任务。
