消息渠道让用户在聊天中使用 OMA 智能体。渠道接收消息，按准入规则和身份配置创建或复用[会话](/docs/zh/sessions)，再把智能体的回复发回对应的聊天或话题。

## 选择消息平台

| 平台 | 接入状态 | 接入方式 |
| --- | --- | --- |
| 飞书 | 已支持 | [扫码绑定或填写应用凭据](#飞书接入) |
| [钉钉](#钉钉接入) | 尚未开放 | — |
| [企业微信](#企业微信接入) | 尚未开放 | — |
| [个人微信](#个人微信接入) | 尚未开放 | — |

## 配置渠道

在目标工作区打开 **渠道 → 新增渠道**，选择平台并连接机器人。然后选择默认智能体和[运行环境](/docs/zh/environments)，按需挂载共享密钥库、文件、记忆存储或 Git 仓库。版本策略可以固定为指定版本，也可以让新会话使用最新版本。

连接机器人赋予渠道收发消息的权限。要让消息进入智能体，还需要决定谁能使用这个入口，以及以谁的身份执行。

| 设置 | 如何选择 |
| --- | --- |
| 渠道准入（`mode`） | 选择开放（`open`）或配对（`pairing`），决定哪些聊天可以接入。 |
| 执行身份（`identity_resolution.mode`） | 选固定身份（`fixed`）让获准消息使用指定身份；选范围配对（`pairing`）按渠道内的私聊用户或群确定身份和智能体。 |
| 工具凭据 | 需要按人访问外部服务时使用私聊个人授权。需要多人共用服务账号时，显式挂载共享密钥库。 |

创建渠道时可以通过 [渠道 API](/docs/zh/api/channels/create-channel) 指定身份解析方式。收到消息后，OMA 根据渠道配置确定会话归属。

### 私聊自助配对

使用范围配对时，首条符合准入规则的私聊消息会触发自助配对。OMA 按发送者创建或复用个人身份，将该私聊绑定到默认智能体，然后处理原消息。后续消息使用已有配对及其智能体和版本。

如果准入和执行身份都设置为 `pairing`，还可以在 **私聊配对授权** 中选择已有的 ENV OAuth 客户端。这适用于首次使用前就需要个人凭据的服务。用户先收到授权卡，完成授权后，OMA 将凭据写入个人密钥库、激活配对并继续处理首条消息。解除配对后，仍获准的用户可以重新配对，沿用原个人身份和密钥库。

### 对话中按需授权

工具也可以等到实际调用时才请求授权。MCP 服务可以返回 OAuth 质询；通过 Bash 运行的 CLI 可以使用原生沙箱 OAuth 入口请求连接。普通 Bash 命令不会自动触发授权。

当私聊中出现 **等待授权** 时，原消息发送者点击 **前往授权**，核验账号并同意外部服务授权后，等待中的工具调用继续执行。已有凭据有效或可以刷新时，工具直接继续。共享凭据需要重新授权时，由相应密钥库的管理者处理。

## 在聊天中管理会话

| 命令 | 用途 |
| --- | --- |
| `/help` | 查看当前机器人支持的命令 |
| `/status` | 查看当前会话状态 |
| `/new` 或 `/reset` | 让下一条消息创建新会话 |
| `/resume` | 列出当前聊天或话题下可恢复的会话 |
| `/resume 会话ID` | 切回指定的兼容历史会话 |
| `/stop` | 停止当前任务 |

恢复历史会话时，OMA 会核对渠道应用、聊天范围、执行目标、版本和挂载资源。在固定身份渠道中，发送 `/new` 后，下一条消息会按当前渠道配置创建会话。对于已配对的聊天，`/new` 只重置会话绑定，下一条消息仍按配对记录选择智能体和版本。

## 飞书接入

### 扫码绑定

在 **渠道 → 新增渠道** 选择 **飞书**，在 **连接应用** 中扫码并确认授权。

### 手动接入

1. **创建应用并添加机器人。** 登录 [飞书开放平台开发者后台](https://open.feishu.cn/app)，选择 **创建企业自建应用**，填写应用名称和描述。进入应用后，在 **添加应用能力** 中添加 **机器人**。已有应用可直接检查机器人能力和下列配置。
2. **开通权限。** 在 **权限管理 → 批量处理 → 批量导入/导出权限** 中选择 **导入**，粘贴以下 JSON 并提交申请。此清单与 OMA 扫码绑定时申请的权限一致。

   ```json
   {
     "scopes": {
       "tenant": [
         "application:app_slash_command:read",
         "application:app_slash_command:write",
         "application:application:self_manage",
         "application:bot.basic_info:read",
         "application:bot.menu:write",
         "cardkit:card:read",
         "cardkit:card:write",
         "contact:contact.base:readonly",
         "docs:document.comment:create",
         "docs:document.comment:delete",
         "docs:document.comment:read",
         "docs:document.comment:update",
         "docs:document.comment:write_only",
         "docx:document.block:convert",
         "docx:document:readonly",
         "docx:document:write_only",
         "drive:drive.metadata:readonly",
         "im:chat.members:bot_access",
         "im:chat:create",
         "im:chat:read",
         "im:chat:update",
         "im:message",
         "im:message.group_at_msg.include_bot:readonly",
         "im:message.group_at_msg:readonly",
         "im:message.p2p_msg:readonly",
         "im:message.pins:read",
         "im:message.pins:write_only",
         "im:message.reactions:read",
         "im:message.reactions:write_only",
         "im:message:readonly",
         "im:message:send_as_bot",
         "im:message:send_multi_users",
         "im:message:send_sys_msg",
         "im:message:update",
         "im:resource",
         "wiki:node:read"
       ],
       "user": [
         "contact:user.employee_id:readonly",
         "offline_access"
       ]
     }
   }
   ```

3. **填写应用凭据并启用渠道。** 在飞书应用的 **凭证与基础信息** 页面获取 **App ID** 和 **App Secret**。在 OMA 的 **渠道 → 新增渠道 → 飞书 → 连接应用** 中填写两项凭据，保存并启用渠道。确认渠道已连通后，返回飞书开放平台。
4. **订阅消息事件。** 在 **事件与回调 → 事件配置** 中选择 **使用长连接接收事件**，添加接收消息事件 `im.message.receive_v1`。
5. **订阅卡片回调。** 在 **事件与回调 → 回调配置** 中选择 **使用长连接接收回调**，在 **已订阅的回调** 中添加 **卡片回传交互**（`card.action.trigger`）。
6. **发布应用。** 在 **版本管理与发布 → 创建版本** 中填写版本信息，把验收账号加入应用可用范围，然后提交发布。如果组织要求审批，等版本发布后再验证消息收发。

### App ID 唯一绑定

一个飞书 App ID 在整个 OMA 实例内只能绑定一个未删除渠道，跨工作区和组织同样生效，因此同一个飞书应用不能同时接入两个渠道。

| 渠道状态 | 是否占用 App ID |
| --- | --- |
| 已绑定应用（`binding_status` 为 `bound`） | 占用 |
| 已停用但已绑定应用（`enabled` 为 `false`） | 占用 |
| 已删除 | 释放 |
| 尚未绑定应用（`binding_status` 为 `unbound`） | 不占用 |

创建或编辑渠道时，如果该 App ID 已被其他渠道占用，接口返回 HTTP 409，错误类型为 `conflict_error`，错误码为 `channel_app_already_bound`；控制台在渠道表单上提示「该应用已绑定到其他渠道，请换一个应用。」。要让另一个渠道使用该 App ID，先删除占用它的渠道，或改用其他飞书应用。错误结构见[错误](/docs/zh/api/errors)。

### 添加「新建会话」菜单

在飞书开发者后台的 **机器人 → 机器人自定义菜单** 添加「新建会话」，响应动作选择 **推送事件**，事件 ID 填写 `chat_new`。在 **事件与回调 → 事件配置** 中通过长连接订阅机器人自定义菜单事件 `application.bot.menu_v6`，然后发布应用版本。扫码绑定新应用时会同时申请订阅此事件。

此菜单用于机器人私聊，效果与 `/new` 相同。机器人确认后，下一条私聊消息会创建新的 OMA 会话。

### 验证消息收发

在 OMA 渠道详情页运行 **连接检测**。用应用可用范围内的账号私聊机器人，确认能够收到回复。需要群聊时，可选固定身份，将机器人加入群并 @ 它。

开启 **话题回复** 后，群聊按话题使用独立会话。选择 **主会话回复** 时，机器人在群主会话回复。群聊使用当前执行目标显式挂载的共享密钥库。

单聊默认使用 **主会话回复**。可以在渠道配置的 **身份与回复** 中单独选择 **话题回复**。开启后，在单聊主窗口发新任务会创建新话题，在话题内发消息会继续该话题的会话。

## 排查问题

| 现象 | 检查项 |
| --- | --- |
| 机器人收不到消息 | 检查渠道是否已启用、绑定和连通。飞书还需检查应用可用范围、消息事件订阅及群聊中是否已 @ 机器人。 |
| 消息提示待配对或身份停用 | 检查该聊天的准入、配对状态和执行身份状态。 |
| 保存渠道提示应用已绑定 | 该 App ID 已被其他未删除渠道占用，停用渠道仍占用。删除占用它的渠道，或改用其他飞书应用。 |
| 授权卡无法完成 | 使用原发送者账号，检查 OAuth 客户端的允许域名及回调地址。 |
| 智能体找不到挂载文件 | 渠道 API 的默认文件路径为 `/uploads/{file_id}`，沙箱内从 `/mnt/session/uploads/{file_id}` 读取。Git 仓库位于 `/workspace/` 下配置的挂载路径。 |
