自托管时，OMA 控制平面与您的 worker 共同参与处理会话。部署者需要配置访问控制、网络和运行环境，并确认控制平面、模型提供商与外部工具的数据流符合自己的要求。

## 您的责任

* **沙箱镜像质量和运行时加固。** OMA 不会检查或验证您的沙箱镜像。请遵循最佳实践，例如移除不必要的 Linux capabilities、以非 root 用户运行，以及使用只读根文件系统。
* **网络出口控制。** 您的沙箱的网络访问由您的 VPC 和防火墙规则决定。如果没有出口限制，被攻破的工具执行可以访问任意外部主机。请将出站流量限制为仅您的工具所需的端点。
* **服务密钥的存储和轮换。** 环境服务密钥（`ANTHROPIC_ENVIRONMENT_KEY`）可访问环境工作队列，也可读取同一环境的会话及读取、提交其事件。请安全存储凭据，避免放入沙箱镜像或日志，并按部署的凭据管理流程处理泄露。
* **隔离不受信任的工作负载。** 根据实际用户和工作负载的信任边界配置工作区、环境和 worker 权限；独立环境本身不等同于单用户隔离。
* **工具执行的影响范围。** 工具在您的沙箱内运行，拥有您的进程所具有的全部权限。请对进程用户应用最小权限原则，并仅挂载您的工具所需的目录。
* **日志保留和会话内容。** 对话内容和工具输入、输出可能经过 worker、OMA 控制平面及模型提供商。请按部署的数据流和保留策略管理和脱敏数据。

## OMA 无法为您做的事情

* **得知您的密钥已泄露。** 如怀疑凭据泄露，请按部署的应急流程处理，并核实撤销和替换是否生效。
* **验证您的 worker 构建。** OMA 不会检查您的沙箱镜像或运行时。您镜像中的供应链攻击无法从控制平面检测到。
* **在您的沙箱内隔离工具。** OMA 的安全边界止于沙箱。在该边界内如何将各个工具执行相互隔离完全是您的责任。
* **在您的环境中强制执行数据保留。** 一旦会话内容到达您的 worker，它就超出了 OMA 的数据生命周期控制范围。
