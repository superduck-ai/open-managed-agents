A session budget limits the cost OMA tracks for one session. You can set a USD budget at session creation; a deployment can also specify a budget for each session it starts. The tracked cost is not necessarily your actual bill, and an in-flight request can exceed the limit.

## Create a session with a budget

Set `OMA_BASE_URL` and `OMA_API_KEY` as described in [Authentication](/docs/en/api/authentication), and prepare `AGENT_ID` and `ENVIRONMENT_ID`. The session's model must have a price configured in OMA.

```bash
session=$(curl -sS --fail-with-body "$OMA_BASE_URL/v1/sessions" \
  -H "x-api-key: $OMA_API_KEY" \
  -H "content-type: application/json" \
  -d "{\"agent\":\"$AGENT_ID\",\"environment_id\":\"$ENVIRONMENT_ID\",\"budget\":{\"type\":\"limit\",\"max_list_cost\":{\"amount\":\"2500\",\"currency\":\"USD\"}}}")
SESSION_ID=$(printf '%s' "$session" | jq -er '.id')
```

`amount` is a positive integer number of cents as a string, without leading zeroes: `"2500"` means 25 USD. `currency` supports `USD`. A budget can only be attached at creation; it cannot be added later to a session created without one.

## Metering and the limit

OMA prices input, output, and cache tokens using configured model prices; each model request's cost is rounded to cents. Web search is metered at one cent per request, and active time at eight cents per hour, rounded to cents. The session's `usage.list_cost` is the accumulated amount used for budget enforcement; it may differ from the provider's bill.

After worker events are persisted, OMA aggregates usage. On reaching the budget it emits `session.usage` and `session.status_idle` with `stop_reason` of `budget_reached`. Because the check follows request completion, the final total can exceed the limit. At the limit, new work-starting events such as `user.message` are rejected; settlement events such as tool confirmations, tool results, and interrupts remain accepted.

## Change or remove a budget

A session created with a budget can have its cap updated. The new amount must exceed the current `usage.list_cost`:

```bash
curl -sS --fail-with-body "$OMA_BASE_URL/v1/sessions/$SESSION_ID" \
  -H "x-api-key: $OMA_API_KEY" \
  -H "content-type: application/json" \
  -d '{"budget":{"type":"limit","max_list_cost":{"amount":"4000","currency":"USD"}}}'
```

Send `{"budget":null}` to remove the budget. Once removed, it cannot be re-added to that session; raise the cap instead if you need to retain a limit. Updating clears the reached marker; inspect the session status and send a new message as needed to continue work.

## Inspect usage

Retrieve the session's `budget` and `usage.list_cost`, or inspect `session.usage` and status events in the [session event stream](/docs/en/events-and-streaming). Threads share the session budget. A deployment budget applies to each session it starts, not to cumulative deployment spend; changes apply to subsequent sessions.
