本指南使用 Docker Compose 启动 PostgreSQL、Redis、MinIO、e2b-local、OMA Server 和 Web 控制台。

## 前置条件

- Linux Docker Engine 20.10+，或 macOS 上的 OrbStack
- Docker Compose
- Git
- `just`（用于仓库提供的便捷命令）

<Steps>
  <Step title="克隆仓库">
    ```bash
    git clone https://github.com/superduck-ai/open-managed-agents.git
    cd open-managed-agents
    ```
  </Step>

  <Step title="初始化本地配置">
    ```bash
    just init-compose-config
    ```

    该命令从无密钥模板创建 `deploy/docker-compose/oma-server.local.yaml`，并且不会覆盖已有文件。
  </Step>

  <Step title="填写运行凭证">
    编辑 `deploy/docker-compose/oma-server.local.yaml`。至少检查上游模型凭证、对象存储和 Sandbox 配置。

    <Warning>
      不要把真实 API key、私钥或生产凭证提交到 Git。生成的本地配置已被仓库忽略。
    </Warning>
  </Step>

  <Step title="启动服务">
    ```bash
    docker compose up -d
    ```

    默认地址：

    - 控制台：`http://localhost:28080`
    - API：`http://localhost:38080`
  </Step>

  <Step title="检查健康状态">
    ```bash
    curl http://localhost:38080/healthz
    ```

    预期响应：

    ```json
    {"status":"ok"}
    ```
  </Step>

  <Step title="调用第一个 API">
    开发 seed 默认创建 API key `sk-ant-local-default`。

    ```bash
    curl http://localhost:38080/v1/models \
      -H 'Authorization: Bearer sk-ant-local-default'
    ```
  </Step>
</Steps>

## 查看运行状态

```bash
docker compose ps
docker compose logs -f oma-server
```

## 停止本地环境

```bash
docker compose down
```

添加 `-v` 会同时删除 Compose 管理的数据卷。除非你明确不再需要本地数据库和对象存储数据，否则不要使用它。
