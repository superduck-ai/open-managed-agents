# Files feature map

Run `just verify-be files doctor`, then all nine local functional scenarios below and [Files performance](files-performance.md). Each local run compiles the actual backend and starts isolated PostgreSQL, Redis, three NATS nodes and MinIO. Only `files generated` requires a Worker image and FUSE. Run `files doctor generated` before it. [Cloud storage](cloud.md) uses an explicit private configuration and is separate from this local suite.

## Entry points and fixtures

- HTTP: `POST/GET /v1/files`, `GET/DELETE /v1/files/{id}`, `GET /v1/files/{id}/content`, header `anthropic-beta: files-api-2025-04-14`.
- Implementation: `internal/files/handler.go`, `internal/db/files.go`, `internal/storage/`, `internal/cleanup/worker.go`.
- Assertions: `tests/livefiles/`. `harness_test.go` owns HTTP, DB and S3 observations, tenant creation and downloadable fixtures. Runtime SQL uses existing DB APIs backed by Yourbatis.
- Config: isolated Files runs set `max_file_bytes=65536`, `workspace_limit_bytes=98304`. Tests reject other settings. Fixtures use the disposable `verify-be` bucket; no shared API/database/storage is supported.
- Evidence: `tmp/verify-be/<run-id>/report.json`, `report.md`, `tests.jsonl`, separate tool stderr and backend logs. Stage markers are emitted only after assertions succeed. Process/Compose cleanup is required for pass.

## Contract and exclusions

Uploaded files are intentionally not downloadable. Their bytes are checked directly in MinIO and their public content endpoint must reject access. A separate downloadable fixture uses `DB.CreateFile` and the real object store. It verifies the download endpoint, not sandbox output generation or the Filestore projection.

Only `storage` seeds a cleanup task to isolate the basic loop assertion. `recovery` proves automatic enqueue and the first retry using an isolated Go S3 fault proxy. Its controls never enter the production backend. Proxy observations retain methods, paths and times, not credentials or object bodies.

Expiry hides outputs; physical cleanup is verified after Session deletion. Archive retains files. `attachments` seeds Agent metadata through DB APIs and output fixtures through `PutFilestoreFile`, but creates Sessions and mutates attachments over HTTP. `generated` covers the actual Worker output producer separately in `tests/liveworker/files_generated_test.go`.

Cloud IAM/network behavior requires a separate `files cloud-storage` run. Local invalid credentials, injected permission failures, multipart interruption and version cleanup do not certify an external S3 deployment. `files exhaustion` validates the ten-attempt terminal state with accelerated scheduling; `files recovery` validates the first real delay. `files performance` is a serial latency baseline, not concurrent capacity verification.

`generated` preallows Write because interactive confirmation on a publicly allocated sandbox invokes the production E2B timeout extender. The local Docker Provider does not implement that cloud API. `chat tools` separately verifies SDK approve/deny with real Worker execution; public E2B renewal is not certified here.
