# 会话输入请求幂等

`POST /v1/sessions/{session_id}/events?beta=true` 支持可选 `Idempotency-Key` 请求头，首尾空白在入口移除，上限128字节。省略时沿用每次提交新输入的行为，不改变已有客户端。

同一组织、工作区和会话内，相同请求标识及相同事件数组返回原事件ID；不同事件数组复用标识返回409。事件数组按JSON对象键序及信封空白规范化后计算SHA-256，正文中的空白保留，整数与浮点数字面量保持原精度，不经IEEE双精度转换。数组顺序属于请求内容，不能调换。认证和会话访问授权始终先于回执读取。

`session_input_requests`只保存请求标识、请求指纹、原事件ID、已结算输入ID及交接确认，不复制事件正文、模型执行阶段或工具记录。首次写入复用原Session行锁及同一个Yourbatis事务：先读取已存在回执，未命中才执行原输入校验、事件写入与结果更新，最后保存回执。回执保存失败会回滚事件；并发重试在同一行锁内读取已提交回执，不能产生另一份输入。回执查询与交接确认均绑定组织、工作区、会话UUID及请求标识。

重试在预算、暂停或归档等当前状态校验前核对原回执；这只允许返回已接受的原请求，不允许这些状态下创建新输入。预算过滤产生空响应时也保存空回执，后续重试不能在预算变化后意外执行原已过滤请求。重试从原事件和对象存储恢复响应，大正文继续复用现有payload存储。

交接确认仅表示现有公开事件交接函数已经成功返回，不表示模型开始或执行完成。已确认请求的重试不再次广播、创建Webhook或唤醒Worker。交接尚未确认时，以原稳定事件ID重新走现有传输：已处理的消息和工具确认不再次投递；控制输入若已不再待处理则继续核对后续原事件，其他传输错误照常返回，不吞掉未确认故障。重复发布的稳定ID沿用既有Worker传输去重，不创建另一套执行队列。

渠道发送普通消息时，根据渠道类型、渠道ID、应用账号及回复锚点消息ID计算稳定请求标识，完整合批来源序列仍写入输入metadata。不同内容复用同一锚点不能绕开冲突检查。接口幂等只解决“OMA是否已经接受原请求”；渠道在平台回调成功前持久保存尚未提交的消息，以及批次形成、平台卡片和文件交付回执，仍需分别实现和验收。

卡片停止、审批、问卷回答和取消使用可信交付回执生成稳定请求标识，覆盖渠道类型、渠道、应用、会话、原输入、平台卡片、作用域、聊天、操作者与交互目标。结果不参与标识计算，同卡同目标的相反答案由请求指纹冲突拒绝，回调参数不能提供或覆盖内部标识。

不同入口即使使用不同请求标识，也不能为同一待处理工具提交第二份审批或问卷结果。OMA 在既有 Session 行锁和事件事务内查询已接受的控制事件，统一匹配公开工具事件 ID 及 Worker 历史 ID；同批次重复目标也拒绝并回滚。原请求回执在该检查前读取，因此合法重放仍返回原事件，不会被当成第二份答案。直接复用 session_events，不新增渠道交互状态表；该限制不把多次停止命令扩大为工具答案竞争。
