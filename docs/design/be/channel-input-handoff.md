# 渠道输入持久交接

接收成功的边界是原消息已写入`channel_inputs`。飞书适配器直接注册同步消息事件处理器，复用SDK的解析、机器人身份、过期及提及策略；存储失败返回事件处理错误，由长连接返回失败确认。不能再依赖SDK异步pipeline中的业务回调作为接收确认，因为该回调的错误不会传回消息确认。

公共输入使用项目自有的消息与附件结构。表中的组织、工作区和渠道引用均为UUID，消息唯一键包含渠道UUID、平台类型、应用账号与原消息ID，避免平台重发或不同进程收到同一消息时重复入队。原平台SDK结构不进入数据库或公共执行层；其他适配器可以复用接收、批次、恢复与OMA输入路径。

原消息先成为`received`，认领后为`buffering`。空闲作用域的首条文本立即交接，不等待600毫秒合并窗口；其他作用域正在执行不影响本作用域。作用域已有排队任务或回复时，同一发送人的后续文本保留SDK合批窗口与来源顺序。适配器按作用域和操作者持有SDK的ChatPipeline，并固定为可合批模式；立即交接使用该队列Run刷新已有缓冲，不能通过ChatPipelineManager.Run首建只串行队列，否则之后Push会永久失去合批窗口；命令和附件先交接同一发送人的缓冲文本。合批在同一个Yourbatis事务中锁定全部来源，再保存最后一条消息为批次锚点及完整正文/来源序列，其余来源记录为`grouped`并关联锚点UUID。锚点保存失败会回滚全部来源，不能只剩最后一条消息。

`prepared`表示批次已固定，尚未确认OMA输入。准备完附件和消息内容后，原Session及实际提交内容先落库；恢复复用原文件ID、挂载集合及提交内容，不重新分批。提交使用[OMA输入幂等](session-input-idempotency.md)，响应未知时仍对应同一请求。确认原输入事件ID后变为`accepted`，立即清除锚点和全部来源行的正文、附件引用及准备内容；后续只用原消息标识、Session和输入事件ID恢复。执行状态和模型/工具历史继续以OMA为准。

已有平台卡片ID或已完成的平台交付回执时，输入交接结束，状态为`handed_off`；后续原卡恢复复用`channel_reply_deliveries`。交接结束时清除锚点和全部来源行中的临时正文、附件引用及提交内容，仅保留身份与关联。没有平台ID的发送未知仍保留，不能盲目再发卡片。恢复已接受输入时不再次POST；需要输出文件时仍受独立文件交付回执能力限制，不能把输入恢复当作产物恢复已完成。

持有者以30秒租约认领原消息或批次。活动的已准备批次每10秒续租；合批前缓冲不续租，避免异步合批失败后原消息一直被本进程占有。在线worker每秒扫描可恢复记录，进程停止后约在原租约到期时接管。准备好的批次恢复直接沿用已保存批次，不能重新拆分。已失去持有权的旧实例不能再写入输入回执。会话绑定已改变时保留未确认状态，不把原输入切到另一个会话。

用户主动停止造成的当前回复取消，会关闭该输入交接，防止被取消的未提交输入在恢复后复活。服务停止造成的上下文取消则保留原输入。命令在分派前记录`command_sending`，正常返回后结束交接；进程在命令分派与确认之间停止时，结果保持未知，不自动重复`/new`或`/stop`。完整命令重试与未知结果处理仍需单独验收。

此实现不复制执行状态机，也不代表跨实例不同消息的作用域协调、文件输出回执、按钮/人工交互回执或全部未知交付恢复已经完成。配置改绑后的旧账号消息保持原账号命名空间，不交给新应用执行。
