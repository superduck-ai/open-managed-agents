# Claude Console HAR 设计参考研究

日期：2026-10-24。状态：来源研究；用户已明确以这些文件的样式为主要参考，对应规则已纳入 [设计规范](design-system.md)，首批共享修复进展见 [共性问题梳理](shared-ui-audit.md)。

## 结论

最值得吸收的是表面层次、字段边界归属、选择器行为和尺寸之间的关系。继续使用 OMA 已有的 new-york、Base UI 与 shared/ui，在这些组件上统一规则。原页面已有的圆润尺度和轻边界应当成为比较基线，不应再用全局小圆角、实灰填充和统一蓝色交互状态覆盖。

参考实现存在明确的 CDS 语义变量与共享业务封装。它提供了可核查的设计依据，但当前 HAR 不能证明 OMA 历史上逐行复用了哪些实现，也不能证明采集页面实际启用了全部密度、主题和组件变体。

## 1. 轻盈来自表面关系，而非减少所有圆角

S1 的浅色定义将 `surface-0/1/2` 分别映射到 gray-20/10/0，色值接近白色。`fill-field` 为白色 50% 透明层，`fill-secondary` 为白色 10% 透明层，`ghost-hover` 为中性前景色的 5% 透明层，`ghost-selected` 为 10%。背景、字段和交互反馈各有用途。`表面定义`

OMA 原环境主题已有 `#fcfcfb` 背景、`#0b0b0b` 前景、10% 边界和 12% 输入边界，与该参考的轻表面方向相近。[现有环境主题](../../../web/src/features/managed-agents/environments/styles.css#L8)

**建议融入：** 保留原来的明度和轻重关系，再映射到 Radix 的中性色与透明色阶。页面、浮层、字段、hover、selected 分别使用语义 token。中性色家族先对照原页面比较，不因为换了颜色来源就把每个输入框变成实灰块。Radix 色阶的具体映射属于下一步设计决定，不能从这份 CDS 源码直接推出。

## 2. 焦点、选中与悬停分别表达

S3 的选项高亮使用 `data-[highlighted]:bg-fill-ghost-hover`，已选项使用独立 Indicator；S4 普通操作菜单也使用同一中性高亮。`菜单状态`

S2 的字段配方将背景与边界定义为 `bg-fill-field shadow-field-ring`，焦点单独使用 `focus-visible:shadow-focus`，错误焦点有自己的配方。这说明获得焦点不需要改变整个字段的填充。`字段配方`

不过参考本身的 `--cds-focus-shadow` 确实包含强调色外环和柔光，不能把它描述为“完全没有彩色焦点”。`焦点变量`

**建议融入：** 普通 hover/highlight 使用轻中性色，选中值用对勾，键盘焦点用完整且清晰的轮廓。强调色不应自动变成所有交互的蓝色填充。OMA 的具体焦点颜色仍需与原页面一起评审。

## 3. 一个完整字段只有一个边界所有者

S2 的内部输入配方包含 `bg-transparent border-0` 和 `focus-visible:shadow-none`。带头尾按钮的 TextInput 由外壳应用 `FIELD_FOCUS_RING_WITHIN`，内输入、箭头和清除按钮不重复绘制外环。S3 复用同一字段配方。`外壳实际使用`

OMA 已有 [InputGroup](../../../web/src/shared/ui/input-group.tsx)，无需新建复合字段体系。

**建议融入：** 字段外壳统一负责背景、0.5px 边界、错误和焦点状态。组合控件内部不重复套框。焦点验收必须检查四边、圆角、不同缩放和浮层裁切。用户反馈的“缺一边”仍需在实际 DOM 中复现；静态 HAR 无法确定是 overflow、负边距、边界叠加还是其他原因。

## 4. 统一选择器合同，保留合理的内容变体

S3 高层 Combobox 默认 `mode="select"`，共用普通选择、搜索选择和多选的封装。默认从底部展开、起点对齐、间距 6px，并使用 fixed 定位。选项较多时会启用搜索；其“超过 5 项”阈值是参考产品的实现选择，不作为 OMA 的硬规则。`高层 API`、`定位`

S5 模型选择明确复用该 Combobox，弹层宽度为 `max(anchor-width,20rem)`，说明长内容可以有受控例外。`模型业务封装`

调研基线中的 OMA 有以下差异（当前统一合同见设计规范）：

- [SelectContent](../../../web/src/shared/ui/select.tsx#L43) 默认 `align=center`、`alignItemWithTrigger=true`。
- [ComboboxContent](../../../web/src/shared/ui/combobox.tsx#L57) 默认 `align=start`，从触发器下方展开。
- 部分设置页面将 `alignItemWithTrigger` 改为 false，API backend 字段使用默认值，因此同类字段会出现不同的展开位置。
- Select 默认高度为 h-8，ComboboxInput 复用 InputGroup 的 h-9，列表项目的内边距也不同。

**建议融入：** 保留已有 Select、Combobox、DropdownMenu 的语义分工，统一表单值选择的高度、行密度、下方展开、起点对齐、间距和基本状态。长模型名等内容允许使用明确的较宽档位，限制在视口内。执行操作的菜单继续使用 DropdownMenu。统一不要求替换所有 primitive，也不要求所有弹层同宽。

行为合同应覆盖：单选选择后关闭，多选保持连续选择，仅允许空值的字段可清除，关闭后查询默认清空，取消不修改旧值，Escape 先关闭最上层弹层。S3 对多选关闭、清查询和 Escape 都有显式处理。`关闭分支`、`Escape`。基础键盘及焦点行为继续交给 Base UI。

## 5. 圆角随高度、内边距成套变化

S1 定义了多档尺寸。以 rem=16px、缩放=1 换算，20/24/28/32/40px 控件分别对应 5/6/7/8/10px 圆角，同时调整图标、内边距与嵌套控件尺寸。comfortable 配方为 32px 控件、8px 圆角、22px 嵌套控件。`尺寸配方`、`档位`

S4 菜单的几何关系为：外圆角 = 项目圆角 + gutter。S2 尾部嵌套按钮采用：内圆角 = 外圆角 − (外高度 − 内高度) / 2。`菜单公式`、`字段公式`

OMA 已有基础 10px 以及派生 6/8/10/14px 等圆角。[现有基础尺度](../../../web/src/styles/foundation.css#L64)

**建议融入：** 先保留现有圆润程度，只为真实存在的两三种控件尺寸校准高度、圆角、图标和间距。紧邻包裹的元素按同心关系处理，独立字段不必追随整个页面容器圆角。停止使用“所有控件 4px、所有面板 8px”这类全局压缩规则。无需复制参考的五档密度引擎。

## 6. 按信息对象分组，避免容器重复表达层级

S6 的环境详情使用 `Group`、`Facts`、`KV` 展示网络、软件包等信息；网络限制项按当前类型显示，软件包只列出非空类别。`环境详情分组`

此处证据来自详情展示，不能据此断言参考环境创建表单的全部结构，更不能将“参考没有嵌套表单”写成已验证事实。

**建议融入：** 普通字段组优先使用标题、间距和对齐。只有可独立新增、删除、排序或操作的信息对象才使用容器。不要给页面、区块、字段组各套一层边框。避免重复眉题和说明；仅当文字会改变用户的选择或帮助修复错误时保留。

## 7. 借鉴角色与关系，服从 OMA 已明确的约束

参考定义了多个文字角色，其中部分尺寸低于 12px；它也包含多种动画曲线与时长。它的 hairline 随 DPR 从 1px 变为 0.5px、1/3px、0.25px，焦点另有宽度定义。`hairline`、`焦点和动效`

OMA 继续遵守用户要求：最小文字 12px，单页优先三档、最多四档；结构线与边框使用 0.5px；减少过渡，必要时以 ease-out、250ms 为基础；颜色来自 Radix。焦点指示必须完整且可辨识，不能为追求细线而失去键盘可用性。具体焦点方案单独评审。

## 已纳入设计规范的重点

| 优先项 | 文档需要明确的规则 | 对应已有组件 |
| --- | --- | --- |
| 表面与颜色 | 先保存原页面轻重关系，再做 Radix 语义映射，避免实灰块堆叠 | foundation、环境主题 |
| 选择器 | 默认展开、宽度档位、搜索条件、单多选及关闭行为 | Select、Combobox、DropdownMenu |
| 完整边界 | 一个字段外壳承担边界和焦点，四边不裁切 | InputGroup、Input、SelectTrigger |
| 圆润与对齐 | 保留基线尺度，按高度和内边距校准嵌套圆角 | 现有 radius token、共享尺寸变体 |
| 信息组织 | 用留白和对齐分组，独立对象才使用容器 | Field、现有环境表单 |
| 验收 | 同数据、同视口对照原页面，覆盖默认、悬停、选中、键盘焦点、错误、禁用与展开 | 先环境页，再 Provider 和模型选择 |

`design-system.md` 1.4 已撤销固定 4px 控件、8px 面板以及机械字号替换规则，并明确 HAR 为主要视觉依据。先用环境页的字段、选择器和分组形成对照样本，再调整共享默认值并检查各页面覆盖。

不引入 CDS 依赖，不复制整套压缩脚本、事件补丁、弹簧动效、全局层级管理或自动密度体系。研究阶段未改动产品代码；后续已从回滚基线开始首批共享修复，具体范围与未完成项见 [共性问题梳理](shared-ui-audit.md)。
