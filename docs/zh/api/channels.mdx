渠道和配对接口使用[工作区 API 密钥](/docs/zh/api/authentication)。本文的路径以 OMA 部署地址为前缀。操作流程见[飞书消息渠道](/docs/zh/message-channels)。

## 渠道和应用授权

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/v1/channels` | 列出工作区渠道 |
| `GET` | `/v1/agents/{agent_id}/channels` | 列出智能体下的渠道 |
| `POST` | `/v1/agents/{agent_id}/channels` | 创建飞书渠道 |
| `POST` | `/v1/agents/{agent_id}/channels/{channel_id}` | 更新渠道或设置启停状态 |
| `GET` | `/v1/agents/{agent_id}/channels/settings` | 查看智能体的渠道环境 |
| `POST` | `/v1/agents/{agent_id}/channels/settings` | 在请求体中提供 `environment_id`，设置渠道环境 |
| `GET` | `/v1/agents/{agent_id}/channels/{channel_id}/check` | 检测连接与执行配置 |
| `DELETE` | `/v1/agents/{agent_id}/channels/{channel_id}` | 删除渠道 |
| `POST` | `/v1/channels/credentials/check` | 验证飞书 App ID 和 App Secret |
| `POST` | `/v1/channels/authorizations` | 以 `name` 发起飞书扫码授权 |
| `GET` | `/v1/channels/authorizations/{authorization_id}` | 查询扫码状态 |
| `POST` | `/v1/channels/{channel_id}/qr_sessions` | 对已创建且未绑定的渠道启动或读取扫码流程 |

使用独立授权流程时，将返回的 `url` 用于扫码。查询到 `status: "bound"` 后，将授权响应的 `id` 作为 `authorization_id` 传给创建或更新渠道接口。二维码到期后发起新的授权。也可以直接传 `app_id` 和 `app_secret`，保护好凭据。

工作区列表返回 `data`。渠道对象中的 `binding_status` 反映应用是否绑定，`connected` 反映当前连接状态，`enabled` 是渠道启停开关。已设置执行身份的渠道同时返回 `identity_resolution`、`entry_closed` 和 `connection_status`，固定身份渠道还返回 `identity_id`。

## 创建支持私聊自助配对的渠道

以下示例使用已完成扫码授权得到的 `AUTHORIZATION_ID`。路径上的 `AGENT_ID` 是默认执行智能体。使用与该智能体匹配的 `ENVIRONMENT_ID`。

```bash
curl --fail-with-body -sS -X POST "$OMA_BASE_URL/v1/agents/$AGENT_ID/channels" \
  -H "X-Api-Key: $OMA_API_KEY" \
  -H "Content-Type: application/json" \
  --data @- <<EOF_JSON
{
  "name": "飞书业务助手",
  "mode": "pairing",
  "identity_resolution": { "mode": "pairing" },
  "environment_id": "$ENVIRONMENT_ID",
  "authorization_id": "$AUTHORIZATION_ID"
}
EOF_JSON
```

| 字段 | 说明 |
| --- | --- |
| `name` | 渠道名称 |
| `mode` | 准入模式，`open` 或 `pairing`，默认 `open` |
| `identity_resolution.mode` | `fixed` 使用固定身份，`pairing` 按聊天范围解析。普通旧渠道可省略 |
| `identity_id` | 固定执行的 `idn_` 身份 ID。在 `fixed` 模式提供 |
| `agent_version` | 固定到指定正整数版本。省略时新会话跟随最新版本 |
| `environment_id` | 渠道智能体的执行环境 |
| `vault_ids` | 显式共享的密钥库 ID 数组 |
| `include_thinking`、`include_tool_calls`、`reply_in_thread` | 回复展示与话题策略 |
| `enabled` | 是否启用渠道，默认启用 |

创建固定身份渠道时传入 `"identity_resolution": { "mode": "fixed" }` 和相应的 `identity_id`。范围配对模式由私聊用户或群的配对记录决定具体身份，无需传 `identity_id`。

## 聊天范围配对

下列接口管理执行目标。旧渠道的准入审批记录由 `GET /v1/agents/{agent_id}/channels/{channel_id}/pairings` 查询，通过 `POST /v1/agents/{agent_id}/channels/{channel_id}/pairings/{pairing_id}` 决定准入状态。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/v1/channel_pairings` | 按 `channel_id` 或 `status` 查询范围配对 |
| `GET` | `/v1/channel_pairings/{pairing_id}` | 获取一条配对 |
| `POST` | `/v1/channel_pairings` | 完成待处理的配对 |
| `PATCH` | `/v1/channel_pairings/{pairing_id}` | 修改执行目标 |
| `DELETE` | `/v1/channel_pairings/{pairing_id}` | 解除配对 |

列表支持 `limit` 和 `cursor`，下一页使用响应中的 `next_cursor`。配对记录会返回 `scope_kind`（`direct` 或 `room`）、`status`、`agent_id` 和 `revision` 等字段。

完成配对时，在请求体中二选一传入 `code` 或 `pairing_id`，并提供 `identity_id`、`agent_id`。可选的 `agent_version` 用于固定版本。目标智能体需要配置渠道执行环境。此操作适用于例如收到配对码的群聊。飞书私聊自助配对由渠道完成。

例如收到群聊配对码后，将以下 JSON 提交到 `POST /v1/channel_pairings`：

```json
{
  "code": "从群聊获得的配对码",
  "identity_id": "idn_example",
  "agent_id": "agent_example",
  "agent_version": 4
}
```

改绑或解除配对时，在 JSON 请求体中发送当前 `revision`。修改被并发操作覆盖时重新读取配对，再决定是否重试。个人配对可以修改智能体或版本，身份仍归原操作者。
