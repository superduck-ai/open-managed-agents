Open Managed Agents 提供两种构建方式，每种方式适用于不同的使用场景：

| | 消息 API | Open Managed Agents |
| --- | --- | --- |
| **是什么** | 直接访问模型提示功能 | 预构建、可配置的智能体框架，运行在你控制的基础设施上 |
| **最适合** | 自定义智能体循环和细粒度控制 | 长时间运行的任务和异步工作 |

Open Managed Agents 提供运行智能体所需的框架和基础设施。智能体可以在你管理的环境中读取文件、运行命令、使用已配置的网页工具和运行代码。可用工具、模型缓存和网络访问取决于部署、模型提供商和环境配置。

<Note>
  OMA 是开源、自托管的实现。数据库、对象存储、模型凭证和环境运行器均由部署者管理；文档中提到的“云环境”指由你的 OMA 部署配置的 E2B 或兼容运行器。
</Note>

在控制台的「快速开始」页面，可以通过对话或手动配置创建智能体，也可以从任务模板出发。

## 核心概念

Open Managed Agents 围绕四个概念构建：

| 概念 | 描述 |
| --- | --- |
| **智能体（Agent）** | 模型、系统提示、工具、MCP 服务器和技能 |
| **环境（Environment）** | 会话运行位置的配置：由 OMA 部署配置的云沙箱，或在你自己的基础设施上自托管的沙箱 |
| **会话（Session）** | 在环境中运行的智能体实例，执行特定任务并生成输出 |
| **事件（Event）** | 你的应用程序与智能体之间交换的消息（用户轮次、工具结果、状态更新） |

## 工作原理

<Steps>
  <Step title="创建智能体">
    定义模型、系统提示、工具、MCP 服务器和技能。只需创建一次智能体，即可在多个会话中通过 ID 引用它。
  </Step>
  <Step title="创建环境">
    配置智能体的运行位置：由环境运行器提供的云沙箱，或在你自己的基础设施上运行的[自托管沙箱](/docs/zh/self-hosted-sandboxes)。
  </Step>
  <Step title="启动会话">
    启动一个引用你的智能体和环境配置的会话。
  </Step>
  <Step title="发送事件并流式传输响应">
    将用户消息作为事件发送。智能体根据配置使用工具，并通过服务器发送事件（SSE）传输结果。公开的持久事件可从历史记录中读取；流中的临时增量不属于持久历史。
  </Step>
  <Step title="引导或中断">
    在执行过程中发送额外的用户事件来引导智能体，或中断它以改变方向。
  </Step>
</Steps>

## 何时使用 Open Managed Agents

Open Managed Agents 最适合需要以下条件的工作负载：

- **长时间运行的执行：** 运行数分钟或数小时、包含多次工具调用的任务
- **云基础设施：** 使用部署配置的云沙箱，软件包和网络访问取决于环境设置
- **自托管执行：** 在你控制的基础设施上运行沙箱，并根据部署配置评估数据流和合规要求
- **最少的基础设施：** 无需构建自己的智能体循环、沙箱或工具执行层
- **有状态会话：** 跨多次交互保存对话历史及已持久化的文件
- **计划执行：** 通过[计划部署](/docs/zh/scheduled-deployments)按 cron 计划定期运行智能体

## 支持的工具

Open Managed Agents 提供一组内置工具：

- **Bash：** 在沙箱中运行 shell 命令
- **文件操作：** 在沙箱中读取、写入、编辑、glob 和 grep 文件
- **网页搜索和获取：** 搜索网页并从 URL 检索内容
- **MCP 服务器：** 可连接外部工具提供方；具体工具来自所配置的服务器

请参阅[工具](/docs/zh/tools)了解完整列表和配置选项。

## Beta 功能访问

<Note>
  Open Managed Agents 仍处于测试阶段。不同资源的请求参数和请求头要求不同，请参阅[版本与 Beta 功能](/docs/zh/api/versioning-beta)。
</Note>

要开始使用，你需要：

1. 一个可访问的 OMA 部署和工作区 API 密钥
2. 按所用资源配置需要的 Beta 参数或请求头
3. 一个配置完成且可以启动会话的环境

[MCP 隧道](/docs/zh/mcp-connector)已可通过仅出站的 Connector 连接私有 MCP 服务器。当前版本尚未提供完整的梦境 API；请以[梦境](/docs/zh/dreams)页面顶部的实现状态说明为准。

OMA 在部署中保存会话历史和已持久化的输出。空闲沙箱可能被回收并重建，本地临时文件和进程状态不保证保留。数据保留、加密和合规边界由部署者控制；可根据会话状态通过 API [删除会话](/docs/zh/session-operations#deleting-a-session)，并单独删除上传的[文件](/docs/zh/files)。
