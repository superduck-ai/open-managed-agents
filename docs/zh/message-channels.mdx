飞书渠道把私聊或群聊中发给机器人的消息交给 OMA 智能体，并将回复发回原聊天。渠道使用 OMA 的[会话](/docs/zh/sessions)、[运行环境](/docs/zh/environments)和[密钥库](/docs/zh/vaults)。

## 连接飞书机器人

1. 在 OMA 控制台切换到目标工作区，打开 **渠道 → 新增渠道**，选择 **飞书**。
2. 在 **连接应用** 中使用飞书扫码授权，或填写已发布的飞书应用的 **App ID** 和 **App Secret**。已有应用需要启用机器人能力，并配置消息接收、回复权限和长连接事件订阅。
3. 选择已有的智能体和执行环境。按需要固定智能体版本，或让新会话使用最新版本。选择要共享的密钥库、记忆存储或文件。
4. 保存渠道并运行 **连接检测**。向机器人发送私聊，也可以在机器人所在的群里 @ 它，验证消息能够返回。

手动接入应用时，在飞书开放平台的长连接配置中添加消息事件 `im.message.receive_v1` 和卡片回调 `card.action.trigger`，并发布应用版本。

连接检测用于检查机器人连接。私聊能否执行还取决于渠道准入规则、执行身份和智能体环境。

## 配置消息由谁执行

| 设置 | 决定什么 | 选项 |
| --- | --- | --- |
| 渠道准入 `mode` | 谁能向机器人提交消息 | 开放 `open` 或配对 `pairing` |
| 执行身份 `identity_resolution.mode` | 获准消息由哪个身份和智能体执行 | 固定身份 `fixed` 或范围配对 `pairing` |
| 工具 OAuth | 智能体访问外部服务时用哪份授权 | 当前操作者的个人密钥库，或显式挂载的共享密钥库 |

通过[渠道 API](/docs/zh/api/channels/create-channel)配置执行身份。使用固定身份时，指定一个业务身份。身份启用后，渠道才能用该身份处理新消息。使用配对时，创建请求提供默认智能体和执行环境，由私聊用户或群的范围配对决定最终目标。

### 固定身份

进入该渠道的获准消息使用同一个执行身份。私聊仍按实际发送者查找个人工具授权。同一执行身份下，两位飞书用户各自授权外部服务时使用各自的个人密钥库。

### 私聊自助配对

在显式配置了范围配对且执行入口开启的飞书渠道，用户首次发送私聊后，OMA 会按发送者的飞书身份找到或创建个人身份，绑定到渠道默认智能体，然后处理原消息。用户只需发送一次，渠道明确拒绝的用户仍无法执行。

解除配对后，仍符合准入规则的用户可以重新开始私聊。OMA 会复用原个人身份及已有的密钥库。已有配对使用自己的智能体和版本。

### 群聊范围配对

群成员在群中 @ 机器人后，未配对的群会收到配对提示。拥有管理权限的集成方可以使用配对码[完成绑定](/docs/zh/api/channel-pairings/complete-channel-pairing)，指定执行身份和有环境的智能体。绑定完成后重新 @ 机器人发送问题。群聊只使用显式配置给该执行目标的共享凭据。

旧渠道若只配置了原有的准入配对，仍按现有准入流程处理，已获准用户可用 `/resume` 恢复兼容的历史会话。

## 在飞书对话中授权工具

以 Friday CLI 为例。先让智能体能够在选定环境中运行 Friday CLI，并在 OMA 配置适用的 ENV OAuth 客户端、工具读取的变量名和目标服务域名。使用自定义客户端时，在服务方登记该 OMA 部署的 HTTPS 回调 `/oauth/vault/env-success`。用户在私聊中提出需要访问 Friday 的问题后，实际工具调用才会检查可用凭据。

1. 工具缺少适用凭据，或已有凭据需要重新授权时，回复会显示 **等待授权**。
2. 原消息发送者点击 **前往授权**，通过飞书账号核验后，同意外部服务的 OAuth 授权。
3. OMA 将凭据保存到该操作者的个人密钥库，继续等待中的原工具调用，并在飞书中更新结果。用户无需重发问题。

支持 OAuth 的 MCP 工具也可在调用时触发授权。已有可用凭据或令牌能够刷新时，工具直接继续。若同一变量或连接有匹配的共享凭据，优先使用共享挂载。共享凭据需要重新授权时，请由该密钥库的管理者处理。关于配置与凭据归属，请参阅[身份](/docs/zh/identities)和[密钥库](/docs/zh/vaults)。

## 管理飞书会话

| 命令 | 用途 |
| --- | --- |
| `/help` | 查看机器人支持的命令 |
| `/status` | 查看当前会话状态 |
| `/new` 或 `/reset` | 让下一条消息创建新会话 |
| `/resume` | 列出当前聊天或话题下可恢复的会话 |
| `/resume 会话ID` | 切回指定的兼容历史会话 |
| `/stop` | 停止当前任务 |

开启 **话题回复** 后，群聊按话题使用独立会话。使用 **主会话回复** 时，消息在群主会话中回复。恢复历史时，OMA 会检查当前飞书应用、聊天范围、执行目标、已固定的版本和挂载资源。配置改变后，可以用 `/new` 开启符合当前设置的会话。

## 排查常见问题

| 现象 | 检查项 |
| --- | --- |
| 扫码完成后机器人没有回复 | 确认渠道已启用且已绑定，检查连接状态、应用可用范围和消息事件订阅。群聊中确认机器人已加入并被 @。 |
| 提示待配对或执行身份已停用 | 检查当前聊天的准入和范围配对，以及实际使用的执行身份状态。 |
| 授权卡无法完成 | 用原消息发送者的飞书账号操作，检查目标服务的 OAuth 客户端、允许域名和回调配置。 |
| 已授权仍提示共享凭据不可用 | 在该渠道或执行身份配置中检查共享密钥库及其凭据。 |
