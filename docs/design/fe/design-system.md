# Open Managed Agents Design System

**版本：1.5 以 Claude Console 采集样式为主要参考，保留必要动效**
**范围：控制台、工作台、资源管理、组织设置、Agent 与 Session**
**状态：共享基础已接入 Radix Colors 与语义令牌；视觉规则随本文件持续维护**

视觉设计以用户提供的 `session.har` 与 `platform.claude.com.har` 中的 Claude Console 样式及共享控件配方为主要依据。配色层次、控件比例、圆角关系、边界和交互反馈应向该参考统一；new-york 与 Base UI 负责现有组件实现。先用环境页面形成对照样本，再推广，避免重新批量覆盖页面。HAR 原文与静态分析材料保留本地，不纳入仓库。

## 1. 设计目标

面向开发者、运维人员和组织管理员，提供准确、清晰、紧凑、可预测的操作界面。

视觉方向采用：

- **暖中性色**：降低冷硬感，保持足够的阅读对比度。
- **平面分区**：优先通过对齐、留白和位置组织内容。
- **自然的边界与圆角**：延续项目原有 new-york 页面中清晰、克制的边框质感，控件紧凑，必要容器的轮廓协调。
- **克制的强调**：突出当前任务，减少颜色、徽标和动画干扰。
- **技术信息清晰**：名称、状态、ID、时间、代码具有稳定层级。

统一来自共享组件、页面模式和设计令牌。禁止依靠局部样式覆盖、装饰文案或重复实现控件来维持外观。

规则优先级为：

**用户明确要求 → HAR 中经核实的视觉与交互配方 → 本规范的共享映射 → 组件默认外观。**

原页面是防止视觉退化的比较基线。出现规则冲突时，先检查是否偏离参考的表面、比例与状态关系；不得为了执行旧文档的固定数值而破坏这些关系。

产品语义、权限、数据正确性和可访问性必须保留。

### 1.1 适用范围与规则强度

本规范约束应用自身的界面、控件和文案。用户输入、Agent 生成内容、代码原文、第三方品牌资产和操作系统辅助功能保留其原有语义，不因界面规范被修改。

- **必须／禁止**：评审和验收的约束。
- **默认／优先**：常规方案；偏离时应说明具体任务需要，并收敛到共享组件。
- **按需**：仅在出现实际需求时采用，不构成新增依赖或迁移技术栈的要求。

本文件是前端设计规范的统一入口。当前仅完成首批共享控件修复，不能据此认定当前实现已全部满足；工程行为与权限边界继续遵循仓库约定。

## 2. 技术选型

| 职责 | 统一方案 | 使用边界 |
|---|---|---|
| UI 组件 | 项目现有 shadcn/ui，统一采用 new-york | 优先复用 shared/ui，通过共享令牌适配本规范 |
| 交互基础 | Base UI | 焦点、键盘、弹层、选择行为由库提供 |
| 样式 | Tailwind CSS、语义 CSS 变量 | 不建设页面私有主题 |
| 颜色 | Radix UI Colors | 统一明暗及透明色阶 |
| 图标 | Lucide React | 品牌资产和数据图形允许专用实现 |
| 动画 | 必要反馈使用 CSS | 保留有价值的过渡，按场景统一速度，不引入动画库 |
| 常规布局 | CSS Flex、Grid | 不引入另一套布局框架 |
| 可调面板 | react-resizable-panels | 经共享 Resizable 使用 |
| 排序、跨容器移动 | 优先使用项目已有交互能力 | 仅有实际需求时补充，不把拖拽作为唯一操作方式 |
| 服务端状态 | TanStack Query | 不复制到另一套客户端缓存 |
| 跨组件客户端状态 | 项目现有 React 状态与上下文 | 不为设计统一新增状态管理库 |
| 局部状态 | React state | 简单输入、开关和临时草稿 |
| 路由 | TanStack Router | 可分享的筛选、分页按语义进入 URL |
| 数据表格 | TanStack Table | 使用统一表格外观 |
| 复杂表单 | TanStack Form、Zod | 简单表单不强制引入复杂状态层 |

仓库使用 new-york、Base UI、Geist 与上述 TanStack 方案；当前已安装 Radix Colors 3.0.0，共享主题开始使用官方明暗与 alpha 色阶；各页面的局部颜色仍须逐项清理。采用 Radix Colors 不要求将 Base UI 替换为 Radix Primitives。

视觉以两份 HAR 中的参考样式为主，实现继续采用项目已有 new-york、Base UI 与 shared/ui。通过共享令牌、尺寸和状态变体适配参考，不把 new-york 默认外观当成不可调整的限制，也不引入 CDS 或并行组件体系。

### 2.1 组件复用是硬约束

**严禁在已有依赖可以正确表达的情况下，自行设计实现组件和行为。**

设计与实现均按以下顺序进行：

1. 先查找项目已有共享组件和同类页面模式，确认可用属性、变体与交互状态。
2. 优先直接复用；无法直接满足时，先组合已有组件。
3. 确认已有组件存在能力缺口后，再检查官方 shadcn/ui new-york 组件和现有 Base UI 能力。
4. 优先补充现有共享封装或必要变体，避免复制出页面专属版本。
5. 以上方式均无法表达真实需求时，才保留最小自定义逻辑。

在页面结构设计时就确定主要控件与现有组件的对应关系，不先画一套独立控件再要求实现。检查复用范围时同时考虑行为、状态与可访问性，不能只因视觉相似就套用语义不同的组件。已有组件的样式如不符合本规范，应统一修正共享实现，避免在页面覆盖。

禁止重复实现：

- 弹层挂载、定位、碰撞处理、点击外部关闭。
- Escape、焦点陷阱、焦点恢复。
- 菜单和选择器的键盘导航。
- Checkbox、Switch、Tabs、Combobox 清除行为。
- 普通面板的拖动、宽度计算和范围限制。
- 已有库能够表达的拖动排序。
- 已有共享搜索、筛选、分页、空状态和页面头部。

共享封装没有暴露底层能力时，应补充共享封装。

业务校验、流式状态机、图形坐标算法可以自定义，但不能因此重写周围的通用控件。

### 2.2 依赖治理

优先使用当前项目已有的组件、依赖、hooks 和工具函数。同一职责只保留一个主要方案；已有实现能够满足需求时，不新增同类依赖或另一套组件体系。

只有明确的实际需求无法由现有能力、官方组件或最小组合满足时，才评估新增依赖，并说明具体能力缺口、现有方案为何不足及维护成本。Radix Colors 按本规范承担统一配色来源，不因此引入 Radix Primitives 或替换现有 Base UI。

feature 只使用共享交互组件，原始 Base UI 导入限制在共享 UI 层。无引用的组件和依赖应清理。

## 3. 颜色系统

### 3.1 唯一来源

所有应用控制的颜色必须来自 **Radix UI Colors**，包括：

文本、背景、边框、图标、图表、代码高亮、遮罩和阴影。

业务代码不得直接使用：

- 页面和组件内硬编码 hex、rgb、hsl、oklch。Radix 官方色值只允许集中导入或固化在主题令牌层，须保留来源与版本。
- Tailwind 内置颜色。
- 随意降低透明度形成的新颜色。
- color-mix 混出的页面私有颜色。

透明背景可使用 `transparent`，继承颜色可使用 `currentColor`；二者不构成额外调色板。需要半透明表面、遮罩和阴影时使用 Radix alpha 色阶，禁止对整个控件设置 opacity 导致文字一起变淡。

用户上传内容、外部品牌资产和系统强制颜色模式不做强行重染。应用控件内由代码绘制的软件包标识保留类别识别色，并映射至 Radix 对应色阶；Python 保留蓝/黄双色。工具权限的允许、询问、拒绝分别使用绿、琥珀、红的语义色，不能在统一中性控件时抹去这些识别信息；图标、选中状态及可访问名称共同表达状态，不能仅靠颜色区分。应用生成的头像、图表和编辑器主题仍须使用统一颜色令牌。

### 3.2 先统一表面关系，再确定色阶

参考浅色主题以接近白色的画布、面板和字段建立微弱层次，使用中性透明层表示悬停和选中。禁止把所有字段统一铺实灰底，或把每层容器都加深来制造区分。

| 颜色角色 | 统一用途 |
|---|---|
| 中性色与其中性 alpha 色阶 | 画布、面板、字段、文字、边界、普通 hover / selected、默认主按钮 |
| Blue | 链接、必要信息状态；不默认用于所有选中背景和字段焦点 |
| Green、Amber、Red | 成功、警告、错误与危险操作 |
| Violet 等补充色 | 具有实际分类需求的图表 |
| Black alpha | 遮罩和必要浮层阴影 |

环境明暗样本采用 Sand 作为共享中性色，使用 alpha 色阶保留近白表面与轻边界。此前深输入边界和蓝色选中底的固定映射已取消；后续页面复用同一映射，不自行挑色。深色主题也按表面角色映射，不简单反转浅色值。

### 3.3 色阶职责

采用 Radix 的角色划分：1–2 为低强度背景，3–5 为交互背景，6–8 为边界，9–10 为实色强调，11–12 为文字。alpha 色在实际底色上合成后检查。

这些职责不是每个字段必须使用第 3 阶底色、每条边界必须使用第 9 阶的命令。首先匹配参考的视觉强度，再验证实际文字及必要控件辨识度。不能因为边界过深，再用更深的背景抵消。

### 3.4 共享语义映射

| 令牌或角色 | 视觉要求 |
|---|---|
| `background` | 接近白色的轻暖画布，深色对应低层画布 |
| `card`、`popover` | 对应面板与浮层表面；不强制每个分组都有底色 |
| 字段填充 | 与画布接近的轻表面，按 Radix 中性 / alpha 候选匹配参考 |
| `foreground` | 清晰的中性正文与标题 |
| `muted-foreground` | 次要信息，保留阅读对比度 |
| `border`、`input` | 分别表达容器与字段的轻边界，不机械统一加深 |
| `secondary` | 轻表面及必要边界，不默认实灰填充 |
| `accent`、hover | 中性轻叠层，用于普通菜单项和工具按钮高亮 |
| `selected` | 中性选中叠层，与对勾、位置或控件语义共同表达 |
| `primary` / `primary-foreground` | 高对比的中性主按钮配对 |
| `ring` | 独立焦点轮廓，默认评审中性方案，强调色仅在有明确需要时使用 |
| 状态前景及背景 | 成功、警告、危险分别配对，不与普通 hover / selected 混用 |
| 遮罩与浮层阴影 | Radix alpha 色，集中定义强度 |

当前映射集中维护于 `web/src/styles/foundation.css`，官方颜色入口为 `palette.css`。基础画布使用 Sand 2；面板浅色 Sand 1、深色 Sand 3；正文 Sand 12；次要文字 Sand 11；轻边界 Sand A4、字段边界 Sand A5；普通悬停 Sand A3，选中 Sand A4。焦点用中性前景细轮廓。该配方已目视核对环境与外观样本，尚不代表全站状态、对比度和缩放验收完成。颜色来源仍为 Radix，参考中的原始 hex 和透明比例用于判断视觉关系，不直接散落到页面代码。

浅色主题的会话 Agent 角色文字、代码字段名和字面量使用 Blue 12，以覆盖时间线和编辑器当前行的浅底；深色主题继续使用 Blue 11。普通链接和图表分别沿用各自语义令牌，不因文字样本修复整体换色。未选中的普通页签使用 `muted-foreground`，避免通过正文颜色降低透明度后不足以阅读。

可阅读的标签、表头、容量和空状态直接使用次要文字语义色，不再叠加透明度削弱对比。加载文字渐变使用前景色与次要文字色，在整个周期中保持可读；保留同步节奏及减少动态效果支持。只读详情不重复展示编辑字段的填写说明。

文字对比度默认至少 4.5:1，必要的非文本控件及状态至少 3:1；按实际表面和语义判断测量对象。状态同时提供文字、图标或形状。任何候选色阶均不自动视为通过。

### 3.5 状态必须分别表达

| 场景 | 默认与悬停 | 选中或按下 | 键盘焦点 |
|---|---|---|---|
| 普通菜单和选择项 | 透明或轻表面，悬停用中性叠层 | 选项用对勾；多选用 Checkbox | 活动项高亮与字段焦点分开 |
| 透明工具按钮 | 透明，悬停用中性叠层 | 明确且克制的按下反馈 | 独立完整轮廓 |
| 导航、分段选择 | 以位置和中性表面区分 | 分段轨道为浅中性层，滑块为浮层表面 | 保留独立焦点 |
| 输入与复合字段 | 轻填充、轻边界，悬停只增强必要边界 | 不因点击或获得焦点整块变蓝 | 外壳统一绘制，填充保持稳定 |
| 中性主按钮 | 保留正文与背景配对，悬停沿中性色变化 | 不临时切换色系 | 不改变子元素前景，不添加无关下划线 |

错误、焦点和选中可以同时存在，应分别表达。禁用保留正确语义和可读标签，不对整个控件降透明度而使文字模糊。参考焦点包含强调色环，但本产品按用户反馈去除默认蓝色填充和发光；保留完整可辨的键盘焦点。

## 4. 字体与层级

单页优先 **三档字号**，最多 **四档**，最小 **12px**。沿用项目现有字体，按参考的正文、标题与技术信息关系组织，不强制全站所有场景只能使用 12/14/20px。

| 角色 | 起始方案 | 使用规则 |
|---|---|---|
| 次要信息与技术元数据 | 12px，行高 16–18px | 不承担主要阅读任务 |
| 正文与控件 | 14px，行高 20px | 同一页面的按钮、字段和列表保持一致 |
| 页面标题 | 20px 或 24px，行高 28px 或 32px | 按参考页面密度选一档，同类页面统一 |
| 必要的浮层 / 区域标题 | 复用现有字号，确需时用 16px | 计入当页最多四档；不把所有弹窗标题强制缩为正文大小 |

紧凑按钮的 xs / sm 文字复用 12px 档，默认按钮复用 14px 档；通过控件高度和内边距区分大小，避免额外产生 0.8rem / 12.8px 档。

以上为样本起点，非自动替换指令。先用字重、颜色和间距区分区块；标题只在需要时使用额外字号。字体角色数量不等于一个页面必须展示全部档位。

正文沿用 Geist Sans，技术标识使用 Geist Mono，中文使用系统无衬线回退。常规字重 400 / 500，关键标题可用 600，不通过强制大写或过粗字重制造层级。数字列使用等宽数字并右对齐。

关键信息不足以容纳时调整布局和优先级，不缩到 12px 以下。Markdown、编辑器和对话内容保留必要语义层级，受应用控制的默认字号同样遵守单页预算；用户内容和辅助字号设置不被改写。

## 5. 间距、对齐与布局

### 5.1 间距尺度

| 间距 | 主要用途 |
|---|---|
| 4px | 紧邻图标与文字 |
| 8px | 控件内部、同行操作 |
| 12px | 紧凑列表、表单内部 |
| 16px | 内容分组、窄屏边距 |
| 24px | 桌面边距、区块间距 |
| 32px | 主要内容分组 |

### 5.2 对齐

- 页面标题、工具栏、表格第一列和正文共用起始基线。
- 同行控件使用一致的高度、文字基线和图标占位。
- 数字右对齐，文字左对齐，表头与数据对齐方式一致。
- 多行文字旁的图标对齐第一行视觉中心。
- 不用空格、不可见字符或中点凑对齐。
- 光学修正集中在共享组件，不在页面反复添加位移。
- 先统一几何尺寸，再检查文字字面、图标视觉重心和内边距；不以图标 SVG 的外框居中作为唯一标准。
- 有行内操作的列表为操作预留稳定列，避免悬停时出现按钮导致正文跳动。
- 仅在精确指针且支持悬停的设备上使用悬停显现的次要操作，并保留键盘焦点显现；触屏不能依赖悬停来发现复制等操作。
- 常显工具按钮不能覆盖正文或代码。长内容需要滚动时，为工具预留滚动区之外的空间，并检查初始和滚动状态下的实际可见内容。

### 5.3 宽度与响应式

- 桌面水平边距 **24px**，窄屏 **16px**。
- 设置与编辑表单默认最大宽度 **720px**。
- 列表、时间轴、监控工作区使用可用宽度。
- 空间不足时先收起次要操作和低优先级元数据。
- 宽表格允许局部滚动，禁止页面出现非预期横向滚动。
- 可调面板在窄屏切换为单面板导航。
- 断点由内容是否可读、可操作决定，使用共享响应式规则，不由单页任意增加。
- 隐藏低优先级信息后，应能从详情或明确的展开入口访问；保留当前任务状态和关键操作。

## 6. 边框、圆角与阴影

### 6.1 边框

结构边框、分隔线、控件轮廓和图表网格线统一为 **0.5 CSS px**。

保留项目原有 new-york 页面中清晰、克制的边框质感。用户已确认原有页面边框的视觉方向较好，后续优化以此为视觉参考，统一到 Radix 语义令牌与 0.5px 线宽；不得以“减少装饰”为由，统一去圆角、加深边框或把所有区域改成硬质方框。

优先用留白表达内容分组；输入控件、独立编辑区域、浮层和必要面板可保留明确边界。边框应帮助识别操作区域和功能归属，不为每一层布局容器增加完整轮廓。

- 同一分组避免同时叠加外框、明显底色块、内部卡片和重复分隔线。
- 容器只是用于排列或限制宽度时，默认不绘制外框，不因使用 Card 组件就保留其完整视觉包装。
- 不通过全局降低边框对比度解决方框感；先删除无功能意义的容器轮廓，再检查必要边界的颜色、圆角与间距。
- 静止、悬停、选中、焦点和错误边界分别承担对应职责，不能让所有边界都具有焦点或错误状态的视觉强度。

图标笔画、数据曲线和品牌资产不属于结构边框，不机械改成 0.5px。焦点轮廓如使用线条也遵循 0.5px，并结合高对比底色或文字装饰表达，不能只依赖低对比细线。不得用粗 box-shadow 模拟边框绕过该要求。

0.5 CSS px 在不同设备像素比和缩放下可能出现取整差异，应在常见 1×、2× 屏幕与浏览器缩放下检查连续性。必要边界不清晰时，先提高对比度或改用有区别的表面，不在页面局部改回 1px。

### 6.2 圆角

以参考中的尺寸比例和现有页面的圆润程度为依据。删除此前 Button / Input / Select 统一 4px、所有浮层统一 8px 的规则。

| 场景 | 统一原则 |
|---|---|
| 普通内容分组 | 使用留白，无需额外轮廓和装饰圆角 |
| 按钮、输入、选择器 | 同一尺寸档共用圆角，与高度及内边距成套定义，见 7.1 |
| 菜单与 Popover | 根据菜单项圆角及 gutter 计算外角 |
| Dialog、Sheet、独立面板 | 依据表面尺度及已有组件校准，通常比内部控件更舒展，不机械缩为 8px |
| 标签、头像、开关 | 按真实语义保留标签轮廓、圆形或胶囊 |

参考菜单使用 **外圆角 = 内圆角 + 包裹内边距**。等距嵌套轮廓使用 **内圆角 = max（0，外圆角 − 实际内缩距离）**。字段内嵌按钮按外壳与按钮的高度差计算内缩，保持视觉同心。

公式仅适用于紧邻包裹关系。容器中的独立字段沿用字段尺寸档，不为了凑同心不断改变圆角。全站共用少量尺寸配方，禁止页面随意覆盖，也禁止为了减少装饰而统一直角。卡片左侧彩色竖线继续禁止。

### 6.3 阴影

页面区块、表格、按钮、输入框不加装饰阴影。

仅必要浮层允许统一的轻阴影：

```css
0 4px 16px var(--shadow-color)
```

禁止多层重阴影、悬停抬升和发光。

## 7. 组件尺寸与操作层级

### 7.1 尺寸

尺寸成套定义：高度、圆角、水平内边距、图标、内嵌按钮一起变化。参考的 28 / 32 / 40px 控件分别对应 7 / 8 / 10px 圆角；这是比例依据，不要求引入完整密度引擎。

| 尺寸场景 | 高度 / 圆角起点 | 使用边界 |
|---|---|---|
| 紧凑工具栏 | 28px / 7px | 空间有限的次要操作 |
| 标准控件 | 32px / 8px | 普通按钮、筛选与紧凑表单 |
| 环境等现有表单 | 保留 36px 作为比较起点，圆角与相邻控件一起校准 | 36px 来自现有页面，不宣称为 HAR 原始档位 |
| 较大控件 | 40px / 10px | 有明确空间与任务需要时使用，不因“主要表单”自动放大 |

每个页面选择少量档位，同一行的 Input、Select、Combobox、Button 必须保持相同高度、文字基线、图标占位与视觉内边距。菜单项目行高及内边距随对应密度统一，不让两个选择组件各用一套默认值。

常规图标以 16px 为起点，较大控件按参考比例检查；Lucide 笔画以现有 1.5 为起点。表格行与长内容根据真实任务确定，不机械压紧。紧凑交互目标至少 24×24px；触屏主要操作命中区域至少 44×44px。

### 7.2 按钮

- 一个任务区域只保留一个主要操作。
- 同组常驻操作最多两档视觉强调。
- 次要操作使用低强调按钮或菜单。
- 创建、提交、授权、删除使用明确文字。
- 常用工具操作可用图标，但必须有可访问名称。
- loading 保持按钮宽度，防止重复提交。

### 7.3 表单

- 标签直接命名字段，不重复“请输入”“请选择”。
- placeholder 不能替代标签。
- 帮助文本仅用于格式、权限后果和高概率错误。
- 错误靠近对应字段，并说明恢复方式。
- 所有表单值选择器统一支持搜索，包括选项较少的普通单选。现有 Select 调用接口保留，内部复用与 Agent 一致的 Popover、Command、搜索栏和选中标记；远程选择器保留服务端检索与分页。操作菜单继续使用 DropdownMenu。
- 清除、多选删除、键盘导航使用库提供的能力。
- 可搜索列表通过组件原生标签接口提供明确的可访问名称，不新增重复可见说明。搜索无结果使用“未找到…”等匹配结果文案，不暗示整个工作区没有资源。

### 7.3.1 避免表单套表单

一个连续的配置或提交任务使用一个清晰的表单区域，字段按任务分组。禁止在表单外框内，为每组字段再添加带完整边框和独立底色的“子表单”卡片，形成层层套框的视觉结构；HTML form 也不得嵌套。

- Dialog、Sheet 或页面面板已提供外层边界时，内部直接排列字段，不再套一层完整表单卡片。
- 字段组优先使用分组标题、间距和留白；确需区分时使用一处分隔线，不同时叠加内外完整边框。
- 输入框自身边界保留，这是可编辑控件的识别线索，不属于需要删除的重复容器。
- 独立编辑器、可重复配置项或具有独立操作与状态的子对象，确需边界时可使用共享容器；不能仅为视觉分组增加容器或拆出独立提交。
- 设计阶段先检查外层页面、弹窗、面板是否已经表达归属，避免实现后再通过调整圆角掩盖重复嵌套。

一次性密钥、令牌等必须完整展示的信息不得省略截断。短屏下保留标题和操作，在内容区滚动展示完整值。空状态内容同样必须受容器宽度约束，不能因长资源名称撑宽页面。

弹窗内部网格默认允许内容收缩；标题和说明中的连续长名称、URL 应在容器内自然换行，保留完整文本。不能只约束弹窗外框宽度，却让内部字段和按钮被内容撑出边界。自定义多列或横向表头仍由对应组件明确布局。

### 7.3.2 选择器的统一合同

- 常规表单值选择默认从触发器下方展开、起点对齐，弹层与触发器间距统一；参考为 6px，环境样本以此起步，碰撞处理交给 Base UI。
- 默认宽度跟随字段，长模型名、成员等内容使用共享较宽变体并限制在视口内；不让页面随意设置独立宽度。
- 不在同类字段中混用“选中项覆盖触发器”与“下方展开”。如有真实特殊需求，用明确共享变体表达。
- 单选选择后关闭；多选保持连续选择；清除仅对可为空字段提供。所有值选择弹层均显示搜索栏，不再按选项数量决定是否支持搜索。列表的状态、创建时间、智能体和部署筛选，以及时区字段，同样复用这套搜索弹层；筛选仍使用原有值和请求参数。
- 打开时高亮当前选中项，选中标记与搜索高亮职责分离；同名选项按原始值区分。关闭后搜索默认清空；取消和无匹配结果不改旧值。Escape 先关闭最上层弹层，不同时关闭外层对话框；焦点恢复及键盘导航由 Base UI 处理。
- 输入、箭头、搜索和清除按钮共用一个字段外壳。外壳统一画边界与焦点，内部输入不重复画框；四边和圆角不能被裁切。
- 选择列表复用共享细滚动条：支持自定义滚动条的浏览器使用 4px 滑块，其他浏览器使用原生 thin；透明轨道、低对比度中性细滑块，悬停时略增强但不加粗；不使用粗轨道、轨道边框或滚动箭头；页面不得单独覆盖共享选择列表的滚动条宽度和颜色。保留滚轮、触控板、键盘和滑块拖动操作。
- 普通选项高亮使用中性叠层，单选用对勾、多选用 Checkbox 表达结果；不把悬停、选中与焦点统一刷蓝。

### 7.4 元数据与状态

版本编号、数量和状态必须来自对应数据，不能写死为示例值。没有可信编号时使用清晰的上下文标签；长名称只压缩名称区域，不能遮挡版本、状态或操作入口，完整名称应仍可查看。

ID、路径和版本优先使用 **12px 等宽裸文本**；日期与时间可使用正文家族的等宽数字。主要阅读内容和需要频繁比较的值使用 14px，不为每个字段加背景或徽标。

相对时间适合扫描，完整时间用于详情和审计，并明确时区。仅在已有数据足够时提供两者，不能制造假精度。

Badge 仅用于状态和真正有分类意义的字段。

必须区分：

- 首次空状态。
- 筛选无结果。
- 加载失败。
- 无权限。
- 功能尚未提供。

不能把未知数据展示成零，也不能把未实现功能永久展示为加载中。

共享 Popover 使用固定定位并约束在 Base UI 提供的可用高度内。长选择列表在弹层内部滚动，搜索框和底部操作保持可达；Command 及列表允许在 flex 容器内收缩，搜索框不随列表压缩。短视口中先将触发器置于可见区域，再验证打开时页面位置、完整焦点轮廓、列表末项和 Escape 焦点恢复。CSS 视口模拟与原生浏览器缩放分别记录，不能互相替代。

## 8. 页面模式

| 页面类型 | 固定结构 |
|---|---|
| 资源列表 | 页面头部 → 搜索筛选 → 表格 → 分页 |
| 对象详情 | 必要导航 → 名称、状态、操作 → 关键属性 → 内容 |
| 设置编辑 | 页面标题 → 按任务分组的字段 → 稳定的提交位置 |
| Session 工作区 | 主对话与当前任务 → 可切换的辅助面板 |

页面头部默认只保留名称、必要数量和主要操作，不增加泛化说明。

不要把每组字段包装成卡片。设置页和弹窗遵循第 7.3.1 节，避免表单套表单；已有外层边界时，内部字段直接排列。不要将详情操作与页面导航混排。

Session 的时间轴和流式状态允许领域实现，周围的 Tooltip、菜单、按钮、Tabs、Resizable 必须复用成熟组件。时间线悬停提示通过共享 Tooltip 的虚拟锚点定位，视口碰撞与 portal 交给 Base UI；不在功能页面手工计算浮层位置。Escape 由当前浮层或检查器处理，不用页面级监听同时清除底层选择。

### 8.1 信息优先级

| 层级 | 内容 | 默认位置 |
|---|---|---|
| 当前任务 | 当前对象、关键状态、下一步操作 | 页面或工作区主要区域 |
| 任务支撑 | 必要字段、结果、筛选、相关属性 | 与其作用内容相邻 |
| 次要信息 | ID、版本、完整时间、诊断详情 | 次级列、详情或展开区域 |
| 无任务价值 | 重复标题、装饰标签、泛化说明 | 删除 |

次要操作进入菜单前，先判断是否高频：刷新、搜索等高频操作保留可见入口。高级配置在相关字段组中按需展开，不在任务开始前增加选择步骤。

窄屏无法同时容纳列表与详情时，详情使用完整内容宽度，关闭后恢复原列表、搜索和折叠状态。桌面分栏继续保留已有拖拽；不要用固定桌面列宽挤掉手机上的详情。时间轴刻度按实际可用宽度减少数量，保持可读字号。

### 8.2 控制台首页

首页以当前工作区的Agent、会话和模型入口为主要内容，环境、部署、记忆存储、凭据保险库、文件和技能为次级资源入口。保留明确的创建Agent、API密钥和文档入口；资源链接携带当前工作区，不固定指向默认工作区。

没有接入真实服务的金额、限额、统计和模型示例不占据首页。首页入口不假装呈现资源数量或最近活动；展示实际列表时，继续遵守真实加载、错误、空状态及权限规则。

## 9. 文案规范

### 9.1 基本要求

- 禁止使用 **U+00B7 中点**作为文案分隔符。
- 独立信息通过列、换行、括号或明确标签分开。
- 不批量替换成竖线、斜杠继续制造噪声。
- 不修改用户正文、代码、ID 或外部原文。
- 同一资源与状态在导航、列表、详情、弹窗中使用同一术语。
- 英文使用 sentence case。
- 所有应用文案进入 i18n，包括可访问名称、错误提示和空状态。
- 面向开发者、运维和管理员使用准确、正式且易懂的表达，保留必要的 API、ID、Agent、Session 术语；首次出现的专业概念只在确有歧义处解释。
- 标题命名对象，按钮命名动作，状态描述事实。避免“赋能”“智能中枢”等无法指向具体功能的造词。
- 名称优先完整显示；按钮避免省略号和多行截断。中文与英文分别审阅实际占位，不按字数机械截短。

### 9.2 删除冗余说明

添加说明前判断：

**删除后，是否影响正确操作、理解必要后果或解释异常？**

不会影响时删除。必要说明放在对应字段或决策点附近。

应保留的内容包括权限范围、密钥展示规则、删除后果、输入格式和错误恢复方式。

### 9.3 眉题

默认不使用 Eyebrow、Overline。

只有提供标题之外的分类、上下文或关键信息时才保留。导航、面包屑已经表达的上下文，不再次重复。

保留前检查：它是否帮助识别当前对象、作用范围或任务阶段？移除后是否丢失信息？仅为了填充留白、增加设计感或重复中英文标题时删除。保留时使用现有 12px 层级，不额外引入全大写、字距和新的颜色。

### 9.4 按场景审阅

| 场景 | 文案要求 |
|---|---|
| 页面标题 | 简短资源名或任务名，避免重复导航上下文 |
| 操作按钮 | 动词加必要对象，例如“添加成员”“保存更改”；上下文明确时可用“保存” |
| 状态 | 使用产品真实状态，例如“运行中”“已完成”“已失败”，不将“处理中”兜底所有状态 |
| 首次空状态 | 说明当前没有什么，并提供一个当前用户有权执行的下一步 |
| 筛选无结果 | “没有匹配结果”，在有意义时提供“清除筛选” |
| 错误 | 说明未完成的动作；原因与恢复操作须有事实依据 |
| 危险确认 | 写明对象与关键后果，确认按钮使用具体动作 |
| Tooltip | 补充图标名称或短说明，不承载必读流程与权限后果 |

错误信息较长时优先换行或展开，不为了保持一行而丢失恢复方法。必要说明不能全部藏进 Tooltip。

### 9.5 文案示例

| 原表达 | 规范表达 |
|---|---|
| “在这里，你可以轻松管理所有成员” | 删除，保留“成员”和“添加成员” |
| “操作成功” | “已保存”或“已复制 ID” |
| “确定要继续吗？” | 明确动作和对象，例如“删除工作区？” |
| 字段“名称”下写“请输入名称” | 删除重复帮助文本 |
| 标题上方重复“AGENT MANAGEMENT” | 删除装饰眉题 |

不得编造错误原因、重试效果或不存在的撤销能力。

## 10. 交互与动画

### 10.1 减少额外决策

- 提供合理、安全的默认值。
- 高级选项放在用户准备配置的位置。
- 不让用户先选择操作方式，再执行已经明确的意图。
- 保留已有选择和输入，避免重复判断。
- 普通保存、刷新、复制不弹确认。
- 删除、不可逆操作、授权扩大、未保存内容丢失时才确认。
- 确认应发生在操作位置和执行时刻，避免连续确认。
- 权限范围和执行对象没有安全默认值时，必须保留明确选择，不以减少决策为由替用户授权。
- 仅当系统真正支持撤销时，才用撤销降低确认成本。
- 点击进入 loading 后立即反馈；250ms 动画时长不作为请求启动、结果显示或状态更新的等待时间。

### 10.2 动画

**克制动效意味着减少多余效果，保留成熟组件中有价值的流畅反馈。** 配色、圆角和动效共同建立柔和、协调的界面，不以直接切换作为默认目标。优先恢复和复用当前组件的原有过渡，不引入动画库，不为动效重写业务流程。

| 场景 | 动效 | 时长基准 |
| --- | --- | --- |
| 弹窗与遮罩 | 淡入淡出，说明前后层级 | 150–200ms |
| 抽屉、详情侧栏 | 按出现方向滑入滑出 | 200–250ms |
| 导航侧栏 | 宽度及必要位置平滑变化 | 200–250ms |
| 折叠区与箭头 | 高度变化、方向旋转 | 200–250ms |
| 下拉菜单、Popover、Tooltip | 轻微淡入淡出；必要时只选小幅位移或缩放 | 120–180ms |
| 按钮按压 | 轻量颜色反馈；位移或缩放仅按场景使用 | 120–180ms |
| Switch | 保留滑块移动与状态色变化 | 150–250ms |
| Skeleton | 正在加载时可轻微呼吸；大面积占位降低强度或静态显示 | 约2s循环 |
| 返回底部 | 按钮轻微显隐，用户主动点击时平滑滚动 | 显隐120–180ms，滚动由浏览器处理 |

以 `ease-out` 为主，只声明必要属性。避免全局 `transition-all`、普遍按压缩放、明显跳动、弹跳、发光、重复 shimmer、逐项入场，以及在同一浮层上叠加明显的淡入、位移和缩放。时长按场景选择，250ms不是所有动效的统一值。

展开和关闭都必须有对应过程，使用Base UI已有的挂载与退场生命周期。焦点恢复、键盘、点击外部关闭、定位和滚动行为继续由已有组件负责；不得为了动画添加请求等待或延迟状态更新。面板拖动、图表刷选必须即时响应。流式文字和表格刷新不反复入场；阅读旧消息或追加内容时保持位置稳定，只对用户主动返回底部使用平滑滚动。

图表若保留首次绘制动效，应使用轻量时长并响应系统偏好，不能依赖图表库默认的长时间入场。启用 `prefers-reduced-motion: reduce` 时关闭或简化上述过渡，Skeleton静态显示，主动滚动使用即时定位。保留清晰的静态状态与真实进度，不展示虚假的百分比。验收同时检查正常与减少动态效果两种模式，不能以静态截图证明过渡自然。

## 11. 可访问性与真实性

- 操作可用键盘到达并执行。
- 浮层关闭后焦点回到合理位置。
- 不用可点击 span 替代完整按钮。
- 不在按钮中嵌套按钮。
- Tooltip 不作为唯一信息来源。
- 状态不能只依赖颜色。
- 长名称、错误信息和关键操作不能因截断而无法理解。
- 刷新、保存、创建必须对应真实行为。
- 不展示硬编码金额、假更新时间或无效筛选。
- 未返回的数据使用缺省符号；明确返回的零值正常显示，不能通过真假值判断将其隐藏。
- 整个服务或数据源尚未接入时，使用简洁的不可用状态与确实可用的入口，不用永久禁用的完整表单或一组全部为缺省符号的指标卡填充页面。个别字段缺失、正在加载、请求失败和无权限仍按各自状态处理。
- 文件容量以服务端字节数为准；缺少容量但已取得文本时按 UTF-8 字节计算，不能将字符数当作字节数。
- 内容加载失败不能显示为空文档，也不能用空字符串作为编辑或下载的替代内容；在原文可用前禁用编辑，失败时在相关位置提供重试。

验证必须覆盖明暗主题、中英文、真实长内容、空状态、错误、无权限和流式更新。

## 12. 主要视觉参考与采用边界

`session.har` 与 `platform.claude.com.har` 中经核实的 Claude Console 样式是主要视觉依据。HAR 原文保留本地，用于区分共享配方、实际业务封装与未验证的运行状态。

必须沿用的关系：

- 近白、轻暖的表面，克制的透明叠层和边界，深色对应清晰但不过重的层次。
- 控件高度、圆角、图标、内边距成套变化；菜单与嵌套按钮保持协调轮廓。
- 中性 hover / selected、独立选中标记，以及与填充分离的完整焦点指示。
- 统一的值选择外壳、弹层定位和列表密度，内容需要时提供受控宽度变体。
- 清晰的正文和标题关系、轻量元数据、稳定对齐与有节制的信息分组。

适配时继续遵守用户的 11 项要求。参考中的低于 12px 字号、按 DPR 变化的线宽、发光焦点与复杂动效不直接照搬；结构边框使用 0.5px，减少多余动效并保留必要的流畅反馈，删除冗余文案与装饰眉题。

颜色链路：**参考的视觉角色与强弱关系 → Radix 候选色阶 → 共享语义变量 → shared/ui → 页面**。

保留现有字体和技术栈，不导入整份参考 CSS，不复制私有 CDS 组件或事件补丁。技术组件复用与视觉向参考统一应同时成立。

## 13. 设计流程与实施顺序

### 13.1 每个页面的设计流程

11 项要求贯穿设计过程。设计稿、交互方案和实现评审均使用第 14 节清单，不等页面实现后再集中修正。

1. **确认任务与复用范围**：明确用户、当前任务、主要操作；查找同类页面和已有共享组件，先用现有能力组织方案。
2. **组织信息与交互**：区分必要内容与次要信息，删除重复入口、无价值说明和装饰眉题；将必要选择放在相关操作位置。先确定功能边界，删除重复容器，避免表单套表单。
3. **确定文案**：直接使用可发布文案，检查受众、术语、动作、长度和中点分隔；不使用占位说明填充界面。
4. **确定视觉规格**：先对照 HAR 参考的表面、尺寸与状态配方，再从共享 Radix 语义令牌、当页字号预算、间距和组件规格中选择，检查光学对齐、0.5px 边框及嵌套圆角；圆角、阴影和动画均有具体功能依据才使用。
5. **补全状态与适配**：在设计中覆盖主要控件状态、明暗主题、长内容、窄屏和键盘焦点，不只提供理想数据下的静态画面。
6. **实现与核对**：按确认的组件组合实现，并检查真实渲染、操作反馈与设计是否一致；发现共性问题时回到共享组件修正。

复用关系与规格可以直接标注在设计稿或任务说明中，无需为每个页面新增流程文档。清单用于发现问题，不要求为了勾选而新增界面元素。

### 13.2 全站迁移顺序

1. 盘点现有组件和页面模式，确认可直接复用的能力与实际缺口。
2. 先以环境页面制作同数据、同视口的对照样本，核对默认及展开、悬停、选中、焦点、错误状态，确认与参考一致且没有损失原页面美观。
3. 根据样本确定共享颜色角色、字号预算、边界及尺寸配方，适配现有共享控件。
4. 再选资源列表、设置页和 Session 工作区验证共享规则，不能先批量替换再补视觉验收。
5. 按本节设计流程迁移其余页面，使用第 14 节清单持续核对。
6. 清理旧样式、重复组件和无用依赖，补充适合自动化的静态检查。

正式采用时指定仓库内唯一规范入口，前端约定链接到该入口；配色、字号、边框、圆角的数值只在共享令牌层维护。

每个试点页面记录颜色来源、状态覆盖、对比度、文案和响应式结果。静态检查适合发现原始色值、非法字号、中点分隔和不必要的 transition；光学对齐、文案质量与信息优先级仍需人工评审。扫描范围限定应用界面，避免误改用户内容、翻译原文和代码示例。

页面迁移、依赖安装、主题实现和浏览器验收需分别记录，不因文档完成而标记通过。

## 17. 逐页实施与截图

隔离样例必须显式覆盖实际功能组件和共享组件的样式源，检查按钮、开关等控件的计算样式与非零尺寸，并目视确认像素。编译成功不代表共享样式完整。发现扫描遗漏后重新采集受影响样本，并标记历史证据待复核。隔离数据必须明确标注，不能代替真实服务流程验收。 冻结的修改前组件也必须纳入样式源扫描；旧类名可能已从当前源码消失。应核对before计算颜色确实来自旧类，不能将默认继承色当作原始设计。

顶部和滚动后的截图必须记录并对齐视口与滚动位置。区分文档与内部容器滚动：文档滚动影响裁剪原点，弹窗或详情容器滚动通常不改变文档原点；不能仅凭文件名包含bottom就判断截图有误。使用截图裁剪坐标时，应根据截图API的坐标系处理实际scrollX/scrollY，避免出现无效空白或遗漏内容。图表截图等待实际绘制完成；截图文件存在、尺寸匹配或DOM结构稳定，均不能单独证明像素内容正确。发现采集方法问题后标记受影响证据待复核，再重新采集，不能继续沿用原来的通过判断。

原始截图及采集记录保留本地，不随代码发布。每个界面须有匹配视口与状态的前后截图及目视核对，不能仅因共享主题生效而标为完成。


### 弹窗视口边界与关闭焦点

宽弹窗也必须在左右各保留至少16px的视口间距；设置较大max-width时，不能把这一间距覆盖掉。高度受视口限制时，长表单内部滚动，标题、关闭和底部操作仍可达。通过受控状态打开的资源弹窗应向Base UI的finalFocus显式提供打开按钮，避免依赖点击是否先聚焦按钮；创建、取消、关闭和Escape均应检查关闭后的焦点。详情编辑返回编辑按钮。


侧栏退出需保留完整挂载生命周期：受控状态收到关闭请求后先让Base UI执行退出，待onOpenChangeComplete(false)再清除选中对象或卸载侧栏。仅设置CSS过渡而在关闭请求时立即卸载组件，不能算恢复了关闭动效。减少动态效果时同样通过primitive的完成回调收敛状态，不另设固定计时器。


保存中的编辑弹窗由调用方禁用取消和关闭，并拒绝Escape及遮罩关闭。共享DialogContent的closeButtonDisabled默认false，禁用交给Base UI Close。失败反馈保持可见，字段可内部滚动；取消保留内容完成退出后再卸载，保存成功的刷新和导航沿用对应功能合同。保险库凭据保存或 OAuth 完成后，写入与本地数据更新立即执行，弹窗先由 Base UI 完成退出，再触发会卸载页面内容的父级刷新；不能提前清空弹窗对象打断退场。失败保留表单和错误。

资源删除、归档等确认弹窗同样保留取消的退出过程，结束后再清除父级选择；处理中禁用操作并拒绝Escape，不能只禁用取消按钮。放弃未保存更改的确认可保持Root挂载，以受控open完成退场；取消保留当前页面，确认后的切换立即执行，不为动画延迟业务操作。

API Key、Webhook 等设置弹窗沿用同一取消生命周期。一次性披露窗口在退出期间保留标题和内容，退出完成后清除展示快照，不能在淡出时清空内容或切换成另一种结果标题。创建和操作处理中禁用取消及关闭并拒绝Escape；失败保留输入和错误，成功后的结果披露与列表刷新按原有合同执行。


### 目录与详情长文本

目录与详情并列时，窄屏单列网格使用可收缩轨道，避免长名称通过最小内容宽度撑开页面。目录项和详情标题可以省略显示，但保留完整名称与路径提示；描述和错误中的连续长字符串在容器内换行。目录加载失败不得展示“暂无数据”或可选择内容的空态；提供就地重试，成功加载后再判断是否为空。


### 工作区表单与目录

短屏创建/编辑表单固定标题和底部操作，正文由普通容器滚动，fieldset只负责字段分组和提交中禁用，避免浏览器对fieldset滚动的特殊处理。失败保留草稿并将错误聚焦到可见正文，提交中禁用取消/关闭并拒绝Escape。创建草稿只在退出完成后复位。稠密目录表格保持可读列宽并内部横向滚动；无匹配时不显示空表头，名称与ID省略显示时保留完整值提示，日期可换行。


### 模型目录与长操作目标

目录标签在有限区域最多展示两行，完整名称与地址通过原始可访问名称和title保留，不能挤出计数、展开箭头或管理入口。操作按钮使用简洁动作文字，冗长模型ID和目标信息可放在可访问名称及完整提示中，不能把按钮排成说明段落。加载失败的重试只重新读取数据，不能意外触发模型同步或配置写入。配置错误留在可滚动正文内，标题与固定操作仍可达。


### 配置保存的退出所有权

配置写入成功后，弹窗先完成自身退出，再由完成回调清除父级编辑对象、卸载条件挂载的表单并重新读取目录。失败保留表单和错误，取消不新增刷新。返回持久化结果的内部提交回调应区分成功与失败，不能把父级捕获后正常返回的失败当作保存成功。始终挂载且已正确缓存退出内容的成熟确认弹窗应保留原有生命周期，不重复改写。


### 资源详情与上传状态

资源详情侧栏在加载、失败、空数据和正常内容中都保留标题与关闭入口。目录加载失败不能显示无描述或空目录这一未经证实的判断，重试只重新读取数据。长标题可限行并保留完整提示，描述和错误在正文内完整换行滚动。上传失败保留有效的文件选择并允许显式重试；无效选择继续禁用提交。取消时保留文件摘要完成退出，退出完成后再清空；不要通过改变受控弹窗key提前卸载。空/加载/错误列表不继承非空表格的列宽与空表头。

技能删除确认使用简洁标题，完整目标名称和不可撤销后果放在可滚动正文，短屏固定标题与操作。上传成功立即保存返回结果并关闭上传弹窗，在 Base UI 退出完成后再打开详情或刷新结果，避免两个界面叠加切换；不得用固定延时替代组件生命周期。

共享选择器的按钮区域必须保持在输入组几何边界内；不能依靠父卡片裁切来遮住负外边距造成的透明盒溢出。校验时同时比较输入组、滚动正文的clientWidth与scrollWidth，完整边界与无多余横向滚动都应成立。


### 共享颜色与原生编辑控件

次要按钮hover使用muted；列表轻悬停与编辑器当前行使用Sand A2；细滚动条使用Sand A7，悬停A8，原有4px/6px几何和按交互显现行为保持。会话细分隔线使用Sand A3，详情分隔线复用border；浮层遮蔽使用Black A6，不以明暗主题的foreground混合模拟阴影。原生文本选择使用Sand A5，搜索匹配使用Violet A3，当前匹配A5，选中文字使用foreground保证清晰。不得抹去软件包与权限识别色。

CodeMirror的Tooltip为0.5px结构边框、8px圆角；搜索面板分隔线、原生搜索输入与按钮均为0.5px，搜索文字不小于12px。键盘焦点在控件内侧绘制，编辑区由原有外框统一呈现中性焦点边界，保留14px外角和四边完整性，不在裁切内容内再叠框。搜索控件属于独立字段，浮动Tooltip属于独立浮层，不能机械套用等距嵌套圆角公式。

共享层不手写显式color-mix；Tailwind透明度工具生成的color-mix需按语义用途单独判断，不以构建产物字面量数量替代颜色验收。


### 选择器统一、结构边界与动效

视觉验收按第 14、15 节的 11 项要求逐项判断，区分真实页面与组件隔离样例；每项记录依据与覆盖状态。截图关系、源码命中或回归数量本身不作为通过标准。原生 200% 全视图重跑、全像素对比度与真实后台执行需单独覆盖。

普通 Select 与资源搜索选择器共用 12px 弹层外角、8px 选项圆角及 4px gutter。Select 列表独立提供 gutter，内部已有分组不再重复叠加。打开时键盘高亮从当前项开始；关闭或重新打开清空临时搜索，不改变已选值；多选在选项切换后继续打开并保留当前搜索，关闭后清空。Agent 服务端分页与精确 ID 搜索不变。工作台保留所有权筛选，但重开时清空临时搜索。

结构线宽必须显式写 0.5px，不能遗漏 Tailwind 默认 `border` 及 `border-t` / `border-r` / `border-b` / `border-l` 等入口，编辑器 Tooltip 同样遵守。图标笔画、数据曲线、与背景同色的连线遮断间隙不属于结构边界，不机械缩细。普通状态保留既有柔和动效；`prefers-reduced-motion` 时通用 spin / pulse 与原共享组件过渡一同停用，加载状态文本保留。
