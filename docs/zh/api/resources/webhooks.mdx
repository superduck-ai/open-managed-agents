---
title: "Webhook"
description: "注册端点、选择事件并轮换签名密钥。"
---

本文描述 OMA 当前合同。[Claude 官方 AWS IAM 映射](https://platform.claude.com/docs/en/api/claude-platform-on-aws-iam-actions)确认了这些管理路由，但未给出完整请求/响应 schema。下述字段和 beta header 尚未与 Claude 做字段级对打验证。

所有请求必须发送 `anthropic-beta: webhooks-2026-03-01`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` / `GET` | `/v1/webhooks` | 创建 / 列表 |
| `GET` / `POST` / `DELETE` | `/v1/webhooks/{id}` | 读取 / 更新 / 删除 |
| `POST` | `/v1/webhooks/{id}/regenerate_signing_secret` | 轮换签名密钥 |

```json
{
  "url": "https://hooks.example.com/oma",
  "name": "production-events",
  "description": "Session and vault lifecycle",
  "enabled_events": ["session.status_idled", "session.error"]
}
```

`url` 和非空 `enabled_events` 数组必填。`name`、`description` 可省略或传空字符串，不接受 `null` 或其他非字符串类型；既有长度上限为 URL/描述 2048 字节、名称 255 字节。POST 更新支持 `url`、`name`、`description`、`enabled_events`、`status`（`enabled` / `disabled`），省略的字段保持原值。

URL 必须使用 HTTPS 和 443 端口，不能包含凭据或 fragment。私有 IP 字面值与 localhost 会被拒绝；部署级 `webhook.allow_insecure` 可允许本地 HTTP 地址。这不等于完整的 DNS 层 SSRF 防护。事件只接受后端白名单，控制台当前提供 17 项（包括 `session.updated`、`session.deleted`），创建时默认不选事件。

端点属于鉴权确定的 workspace。列表返回 `{ "data": [...], "next_page": null }`，控制台的 ID 搜索与排序作用于该集合。详情支持编辑、启停、删除、重置密钥；失败时保留表单或确认框并展示服务端错误。

创建响应包含一次性 `signing_secret`；轮换端点返回新的签名密钥。读取、列表和更新不返回密钥；控制台只在一次性弹窗状态中保留它。消费者使用官方 SDK 验证 Standard Webhooks 的 `webhook-id`、`webhook-timestamp`、`webhook-signature` 标头，并按重复投递场景设计幂等处理。

仅使用数据库订阅、未配置全局 endpoint/key 的部署，需要显式设置 `webhook.worker_enabled: true` 才会执行投递任务。创建订阅本身不会开启 worker。
