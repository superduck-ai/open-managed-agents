OMA 提供 Docker Compose 拓扑，包含运行托管智能体所需的控制面和本地基础设施。

## Compose 服务

| 服务 | 用途 | 默认端口 |
| --- | --- | --- |
| `oma-server` | `/v1` API 和控制台后端 | `38080` |
| `caddy` | Web 控制台和反向代理 | `28080` |
| `postgres` | 资源元数据 | `5432` |
| `redis` | 平台会话 | `6379` |
| `minio` | 文件、技能和批处理产物 | `9000` / `9001` |
| `e2b-local` | 本地沙箱网关 | `3099` |

## 启动完整拓扑

```bash
just init-compose-config
docker compose up -d
docker compose ps
```

配置文件以只读方式挂载到 `oma-server`。应用读取完整 YAML，不会把模板和本地文件合并。

## 本地开发模式

调试后端或沙箱时，可以只在 Compose 中运行 PostgreSQL、Redis、MinIO 和 e2b-local，然后在宿主机运行 Go Server 与 Vite。沙箱回调地址必须从容器内部可达，通常使用：

```yaml
code_session:
  sandbox_api_base_url: http://host.docker.internal:38080
```

## 生产要求

<Warning>
  默认 Compose 拓扑面向本地开发，不应不经加固直接暴露到公网。
</Warning>

生产部署至少需要：

- 将 `env` 设置为 `prod`
- 关闭自动数据库迁移，并在发布流程中显式执行 migration
- 为代码会话挂载稳定的 Ed25519 私钥
- 为密钥库配置稳定的 KEK，并建立轮换与备份流程
- 使用独立的 PostgreSQL、Redis 和对象存储凭证
- 为 API 和控制台配置 TLS、网络边界与访问控制
- 配置日志、指标、备份和恢复验证

开发环境省略代码会话私钥时会在进程内临时生成。进程重启后，旧的 session-ingress JWT 将失效，因此该行为不适合生产环境。
