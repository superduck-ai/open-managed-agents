使用 Open Managed Agents 的费用由两部分组成，单位都是美元：会话消耗的模型 Token，以及会话处于 `running` 时的沙箱时长。一次会话的费用是这两部分之和。Token 数量和运行毫秒数（`active_milliseconds`）都记在 `session.usage` 上。

## Token

模型调用按下面的标价计。`input_tokens` 是未缓存输入，`output_tokens` 是输出。`cache_creation.ephemeral_5m_input_tokens` 和 `cache_creation.ephemeral_1h_input_tokens` 是写入提示缓存的 Token，`cache_read_input_tokens` 是从缓存读出的 Token。MTok 表示每百万 Token。

| 模型 | 未缓存输入 | 5 分钟缓存写入 | 1 小时缓存写入 | 缓存读取 | 输出 |
| --- | --- | --- | --- | --- | --- |
| Claude Fable 5 | \$10 / MTok | \$12.50 / MTok | \$20 / MTok | \$1 / MTok | \$50 / MTok |
| Claude Mythos 5 | \$10 / MTok | \$12.50 / MTok | \$20 / MTok | \$1 / MTok | \$50 / MTok |
| Claude Opus 5 | \$5 / MTok | \$6.25 / MTok | \$10 / MTok | \$0.50 / MTok | \$25 / MTok |
| Claude Opus 4.8 | \$5 / MTok | \$6.25 / MTok | \$10 / MTok | \$0.50 / MTok | \$25 / MTok |
| Claude Opus 4.7 | \$5 / MTok | \$6.25 / MTok | \$10 / MTok | \$0.50 / MTok | \$25 / MTok |
| Claude Opus 4.6 | \$5 / MTok | \$6.25 / MTok | \$10 / MTok | \$0.50 / MTok | \$25 / MTok |
| Claude Sonnet 5 | \$2 / MTok | \$2.50 / MTok | \$4 / MTok | \$0.20 / MTok | \$10 / MTok |
| Claude Sonnet 4.6 | \$3 / MTok | \$3.75 / MTok | \$6 / MTok | \$0.30 / MTok | \$15 / MTok |
| Claude Haiku 4.5 | \$1 / MTok | \$1.25 / MTok | \$2 / MTok | \$0.10 / MTok | \$5 / MTok |

缓存写入和读取相对未缓存输入价的倍率是：5 分钟写入 1.25 倍，1 小时写入 2 倍，缓存读取 0.1 倍。

智能体把 `model.inference_geo` 设为 `"us"` 时，上述每一类 Token 再乘 1.1。`model.speed` 设为 `"fast"` 时，Claude Opus 5 和 Claude Opus 4.8 的未缓存输入为 \$10 / MTok，输出为 \$50 / MTok；缓存倍率叠在这个价格上。

## 会话运行时

例如 2 vCPU、4 GB 内存的沙箱：CPU 0.042336 元/vCPU/小时，内存 0.0066204 元/GB/小时，合计 0.1111536 元/小时。下表按 2026-10-14 中国外汇交易中心人民币对美元中间价换算，1 美元 = 6.7249 元。实际单价以配置为准。

| 项目 | 单价 | 计量 |
| --- | --- | --- |
| CPU | \$0.00629541 / vCPU / 小时 | 2 vCPU |
| 内存 | \$0.00098446 / GB / 小时 | 4 GB |
| 会话运行时 | \$0.01652866 / 小时 | 会话状态为 `running` 的时长 |

把换算结果填进 `runtime_cost.usd_per_hour`。没写这项时，成本页提示未配置，不计算新的运行时金额。只在会话状态为 `running` 时累计，记成 `active_milliseconds` 里的毫秒整数。`idle`（等待下一条消息或工具确认）、`rescheduling` 和 `terminated` 不计。多个线程重叠时仍算一段，不把各线程时长相加。

沙箱里执行命令的时间已经包含在 `running` 时长里，不再另收。这段时长结束时，按当时的单价把美元金额累加进 `usage.runtime_cost_usd`。之后修改 `runtime_cost.usd_per_hour`，只影响之后新结束的时长，已经记下来的金额不变。还没离开 `running` 的这段时间，要等它结束并写入快照后才计入。

## 计算示例

一次使用 Claude Opus 4.8 的会话：未缓存输入 10,000，缓存读取 40,000，输出 15,000，`running` 一小时。

| 项目 | 计算 | 费用 |
| --- | --- | --- |
| 未缓存输入 | 10,000 × \$5 / 1,000,000 | \$0.05 |
| 缓存读取 | 40,000 × \$0.50 / 1,000,000 | \$0.02 |
| 输出 | 15,000 × \$25 / 1,000,000 | \$0.375 |
| 会话运行时 | 1.0 × \$0.01652866 | \$0.016529 |
| 合计 | | \$0.461529 |

## 在哪里查看

`session.usage` 带有各类 Token 计数、`active_milliseconds` 和已经按当时单价算好的 `runtime_cost_usd`。组织控制台的 **分析 → 成本** 按工作区、分组（模型、工作区或服务账号）、模型和时间范围汇总这些已记金额，并显示每日运行时成本。日期按 UTC。相邻两条 `session.usage` 的 `runtime_cost_usd` 差值记在后一条的 UTC 日期上。还没有这个金额的旧快照，按配置里的单价折算。
