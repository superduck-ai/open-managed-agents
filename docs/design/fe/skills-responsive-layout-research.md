# 技能目录的响应式布局依据

核对日期：2026-11-11。本文区分官方规范与 OMA 的设计建议；数值建议需以真实页面验收，不能作为已实现或已通过的证据。

## 结论

不存在一套适合所有产品的“常见屏幕尺寸对应固定列数”标准。断点需要围绕内容、窗口与交互目标选择。技能目录更适合用稳定的间距、有限的列数与适度流动的卡片宽度组织阅读；不能把“固定 360px”或“12 栏”本身视为视觉质量保证。

## 分辨率、视口与内容宽度

[MDN 的 devicePixelRatio 文档](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio)说明：DPR 表达物理像素与 CSS 像素的比例；页面缩放也会影响该比例。不能将显示器的物理像素宽度直接作为网页断点。

需要分别记录：

- 显示器物理分辨率，例如 1920×1080、2560×1440、3840×2160。这里是代表性规格，不是市场份额排名。
- 浏览器视口的 CSS 像素尺寸，以及页面缩放、DPR。物理 4K 显示器不等于网页必然具有 3840 CSS px 的可用宽度。
- 页面内容区实际宽度：视口扣除导航、外边距、滚动条和可能存在的其他面板。屏幕英寸也不能单独决定卡片列数。

## OMA 建议

以下是对本产品的推导，不是上述设计系统规定的通用数值。

1. 由内容区宽度决定卡片列数；同一档位内适度流动，以对齐标题、筛选栏和卡片边缘。侧栏展开与收起都应验证。
2. 为中文描述和长英文名称选择舒适的卡片阅读宽度，并限制超宽屏的内容范围或最大列数，避免一行越来越多、卡片像缩略图。最大内容宽度应同时约束页头与工具栏，不能只给卡片单独加窄容器。
3. 栅格间距和卡片内边距使用项目既有间距令牌，卡片文字字号不随屏幕任意缩小。跨断点换列时宽度适当变化是正常行为，重点是变化后的比例、信息密度和对齐仍协调。
4. 搜索只剩一项、最后一行不足列数时保持当前档位的列结构；不根据结果数量把卡片拉到整行宽度。用户端与超管端共享规则。
5. 在宽度变化时同时检查短屏、键盘焦点、菜单、详情和滚动。列表不可为了“整齐”移除现有功能与信息。

当一行必须铺满且列数从 n 增至 n+1 时，单卡宽度会在断点处下降；这是有限空间分配的结果。不能同时承诺“始终铺满、增加列数、卡片宽度严格不下降”。设计应明确选择阅读宽度、列数、留白之间的平衡。

## 推荐验收矩阵

下列为视口 CSS 像素的代表性测试尺寸，不是设备型号或屏幕英寸的固定映射，也不是访问量统计。

| 场景 | 建议宽度（CSS px） | 配合检查 |
| --- | --- | --- |
| 最窄重排 | 320 | 控件可达、无页面横向溢出；另做原生 400% 缩放 |
| 手机竖屏 | 360、390、430 | 名称、描述、来源、更多菜单、导入入口 |
| 平板与窄窗 | 768、820、1024 | 导航状态、单列/多列转变、短屏与横竖屏 |
| 笔记本 | 1280、1366、1440、1536 | 侧栏展开/收起、信息密度、菜单与详情不遮挡 |
| 桌面大屏 | 1920、2560 | 最大内容宽度、列数上限、对齐与阅读舒适度 |

每个实际断点还需补测前后 1px、短高度（例如 600px）、200% 页面缩放、中英文长名称、单项搜索结果与空结果。原生缩放、不同 DPR 与真实设备触控属于不同验证维度，不能由同一张模拟截图替代。

## 本轮实现与验证

两端共用最大 1600px 的内容容器，按容器宽度在 600、960、1320px 切换为两、三、四列，间距 16px。这些是 OMA 的选择，不是通用规范的强制数值。

2026-11-11 在本地 Chrome 中检查了上述 13 种视口宽度（DPR 1）。侧栏展开时，1024px 为两列，1280–1536px 为三列，1920–2560px 为四列；768/820px 因侧栏占位保留单列。820px 收起侧栏后为两列。全部测试尺寸均无页面横向溢出，卡片标题字号保持 14px。

另检查了三个容器断点前后 1px、单项搜索结果、中英文窄屏页签、390×600px 短屏、1440×600px 详情边界、明暗主题、键盘页签切换和减少动态效果。超管页另在 320、1280、1920px 核对共享栅格。修复了根节点硬最小宽度在 320px 视口与传统纵向滚动条同时存在时导致的横向溢出。

以上是浏览器视口模拟与页面操作结果，未覆盖真实设备触控、不同 DPR 或原生 200%/400% 页面缩放。原生缩放检查因本机锁屏未能执行，不能将 320px 视口模拟称为完整的 WCAG 合规验收。
