# 组织邀请邮件

创建及重发邀请在数据库操作成功后同步发送邮件，复用登录验证码的 SMTP TLS、认证、15 秒超时和截止时间。Console 创建、重发及 Admin API 创建均接入；终态邀请仍不能重发，邮件操作不改变成员资格。没有引入新的队列或自动重试。

## 配置与内容

复用 `auth.smtp`，新增 `auth.console_url`，例如 `https://oma.example.com`。该地址必须为 HTTPS origin，不允许用户信息、子路径、查询或片段；不读取请求 Host 或转发头生成邮件链接。两项未完整启用时仍可创建站内邀请，但明确返回邮件未配置。

邀请邮件同样遵守 `auth.allowed_email_domains`，与登录共用完整域名匹配规则。Console 新建、重发、Admin API 新建和平台后台邀请均在邮件发送器读取组织信息及调用 SMTP 前检查收件域名；未允许的子域名和伪装后缀被拒绝。域名比较不区分大小写，空白名单不限制。SMTP 已启用时，拒绝返回 `email_delivery: failed`，保留已创建的站内邀请；未启用发送时仍返回 `not_configured`。修改白名单并重启后，既有邀请的重发也受新配置限制。

参考 CMA 截图的居中布局、品牌、信封、标题和主按钮，使用 OMA 品牌。正文包含实际组织名、当前操作人的邮箱以及数据库邀请有效期（UTC）；API Key 没有对应用户身份时显示“Organization administrator”，不伪造邀请人。当前没有组织或收件人 locale 数据，邮件主题、正文和默认邀请人统一使用英文。HTML 模板自动转义动态内容，邮件不包含验证码、会话凭据或自动加入令牌。

按钮打开 `/invites`。用户必须用收件邮箱登录，再显式接受；邮件转发不授予他人权限。此次不改变既有首次注册自己的组织和不自动接受邀请的行为。

## 发送结果

创建、重发响应新增 `email_delivery`：`sent` 表示 SMTP 已接受，不能保证最终进入收件箱；`failed` 表示提交失败；`not_configured` 表示发送配置未启用。邀请已保存但发送失败仍返回成功的邀请资源，界面明确提示邀请成功，在说明中显示发送失败数量、允许重发，避免客户端误以为邀请没有创建而重复提交。列表不声称提供历史投递状态。

创建及重发的投递提示复用现有 i18n `msg` 与中英文词条，标题统一确认邀请成功，说明按实际投递状态分别展示：未配置邮件时提示可登录接受站内邀请，使用成功提示；邮件发送失败或缺失状态时使用警告，但不否定邀请已创建，也不把未知状态归因为配置错误。混合批次分别统计发送失败与未知状态的数量，英文区分单复数；空批次不提示。测试分别验证中英文的未配置、失败、缺失状态、混合批次与 SMTP 接受提示。

```mermaid
sequenceDiagram
    participant A as 管理员
    participant S as 邀请接口
    participant D as 数据库
    participant M as SMTP
    A->>S: 创建或重发邀请
    S->>D: 校验权限及状态并提交邀请
    D-->>S: 已保存的邀请及有效期
    S->>M: 提交邀请邮件
    M-->>S: 接受或失败
    S-->>A: 邀请资源与 email_delivery
    Note over A,S: 失败保留站内邀请，可显式重发
```

同步发送存在数据库提交后进程退出导致漏发的窗口，也可能出现 SMTP 已接受但响应丢失后重发造成重复邮件；本期不承诺恰好一次投递。后续确需自动可靠投递时再引入事务 outbox。失败日志不记录收件人、邮件内容或可能携带地址的 SMTP 原始错误。

验证覆盖未配置、SMTP 失败/成功/重试、组织名 HTML 转义、组织/邀请人/有效期/按钮内容，以及公开地址校验；真实邮箱投递需在部署配置 SMTP 和公开地址后单独验收，不能把模板测试当成投递成功。
