会话预算限制 OMA 为单个会话跟踪的成本。创建会话时可设置美元预算；部署也可以设置预算，应用到它启动的每个会话。预算不等同于实际账单，也不能保证进行中的请求不会超出上限。

## 创建带预算的会话

先按照[认证](/docs/zh/api/authentication)设置 `OMA_BASE_URL` 和 `OMA_API_KEY`，并准备 `AGENT_ID`、`ENVIRONMENT_ID`。会话使用的模型需要在 OMA 中配置价格。

```bash
session=$(curl -sS --fail-with-body "$OMA_BASE_URL/v1/sessions" \
  -H "x-api-key: $OMA_API_KEY" \
  -H "content-type: application/json" \
  -d "{\"agent\":\"$AGENT_ID\",\"environment_id\":\"$ENVIRONMENT_ID\",\"budget\":{\"type\":\"limit\",\"max_list_cost\":{\"amount\":\"2500\",\"currency\":\"USD\"}}}")
SESSION_ID=$(printf '%s' "$session" | jq -er '.id')
```

`amount` 是正整数美分的字符串，不含前导零：`"2500"` 表示 25 美元。`currency` 支持 `USD`。预算只能在创建时附加；创建时没有预算的会话不能在之后添加。

## 计量与触顶

OMA 按配置的模型价格计算输入、输出和缓存令牌费用；模型请求费用按请求舍入到美分。网络搜索按每次 1 美分计量，活动时间按每小时 8 美分计算并舍入到美分。会话返回的 `usage.list_cost` 是这些费用的累计值；它用于预算判断，不一定等于供应商实际账单。

工作进程事件持久化后，OMA 汇总使用量。达到预算时会产生 `session.usage` 和 `stop_reason` 为 `budget_reached` 的 `session.status_idle`。由于检查发生在请求完成后，最终累计成本可能超过预算。达到上限后，新的 `user.message` 等启动工作事件会被拒绝；工具确认、工具结果和中断等用于结算已有工作的事件仍可提交。

## 修改或移除预算

已设置预算的会话可以更新上限。新金额必须大于当前 `usage.list_cost`：

```bash
curl -sS --fail-with-body "$OMA_BASE_URL/v1/sessions/$SESSION_ID" \
  -H "x-api-key: $OMA_API_KEY" \
  -H "content-type: application/json" \
  -d '{"budget":{"type":"limit","max_list_cost":{"amount":"4000","currency":"USD"}}}'
```

发送 `{"budget":null}` 可移除预算。移除后不能为该会话重新添加预算；如需继续限制成本，请提高上限。更新会清除触顶标记；请检查会话状态并按需发送新消息继续工作。

## 查看使用量

查询会话的 `budget` 和 `usage.list_cost`，或查看[会话事件流](/docs/zh/events-and-streaming)中的 `session.usage` 与状态事件。多线程共享会话预算；部署预算限制每次新启动的会话，而非所有运行的累计金额。修改部署预算只影响之后启动的会话。
