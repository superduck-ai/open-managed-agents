身份接口使用[工作区 API 密钥](/docs/zh/api/authentication)。身份与渠道、会话和凭据的关系见[身份](/docs/zh/identities)。

## 身份与使用记录

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/v1/identities` | 创建业务身份 |
| `GET` | `/v1/identities` | 列出身份，支持 `status`、`namespace`、`external_subject_id` 和 `q` |
| `GET` | `/v1/identities/{identity_id}` | 查看身份 |
| `PATCH` | `/v1/identities/{identity_id}` | 更新业务身份配置 |
| `DELETE` | `/v1/identities/{identity_id}` | 删除业务身份 |
| `POST` | `/v1/identities/{identity_id}/enable` | 启用身份 |
| `POST` | `/v1/identities/{identity_id}/disable` | 停用身份 |
| `GET` | `/v1/identities/stats` | 根据 `identity_id` 查询使用统计 |
| `GET` | `/v1/identities/{identity_id}/agents` | 查询身份使用的智能体 |
| `GET` | `/v1/identities/{identity_id}/sessions` | 查询该身份的可恢复会话 |
| `GET` | `/v1/agents/{agent_id}/identity_bindings` | 查看智能体的固定渠道和范围配对绑定 |

列表使用 `limit` 和 `cursor` 分页，下一页使用响应中的 `next_cursor`。统计与智能体使用记录可用 `window=7d`、`window=30d` 或 `window=all`，默认 30 天。

### 创建业务身份

```bash
curl --fail-with-body -sS -X POST "$OMA_BASE_URL/v1/identities" \
  -H "X-Api-Key: $OMA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"namespace":"support","external_subject_id":"team_support","display_name":"业务支持"}'
```

`external_subject_id` 和 `display_name` 必填。可以提供 `namespace` 区分业务场景，或用 `enabled` 设置初始状态，默认启用。也可以设置 `auto_memory_store`，指定是否启用身份的自动记忆存储配置。响应中的 `id` 是 OMA 生成的 `idn_` 标识，可用于配置固定渠道或范围配对。飞书个人身份由渠道生成，归属随原操作者保留。

使用[创建会话](/docs/zh/api/sessions/create-session)接口时，支持传入当前工作区内已启用身份的 `identity_id`。

## 身份在智能体下的配置

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/v1/identities/{identity_id}/configs` | 列出身份的智能体配置 |
| `GET` | `/v1/identities/{identity_id}/agents/{agent_id}/config` | 查看保存的配置 |
| `PUT` | `/v1/identities/{identity_id}/agents/{agent_id}/config` | 创建或更新配置 |
| `GET` | `/v1/identities/{identity_id}/agents/{agent_id}/effective` | 查看有效配置，可用 `agent_version` 指定智能体版本 |

写入配置时，使用 `vault_mounts` 设置挂载，用 `disabled_vaults` 声明禁用项。两者都接受密钥库 ID 数组。字段省略时保留已有配置，空数组用于清空对应列表。创建时可用 `revision: 0`，更新时传入读取到的当前 `revision`。新增环境变量统一在运行环境中配置。

## 清理身份

调用 `POST /v1/identities/{identity_id}/clear` 创建清理记录，再用 `GET /v1/identity_cleanups/{cleanup_id}` 查看结果。响应包含 `state` 和 `result`，可检查配置归档、配对解除、入口关闭和保留的共享密钥库。清理保留个人及共享密钥库。

存在运行中的会话或待处理的工具授权时，应先处理这些会话再重试清理。
