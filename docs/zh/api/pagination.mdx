---
title: "分页"
description: "遍历 OMA 列表资源。"
---

不同资源使用不同的分页方式，请以对应接口参考为准。设置 `OMA_BASE_URL` 和 `OMA_API_KEY` 的方法见[认证](/docs/zh/api/authentication)。

- **智能体和会话**：传入 `limit`，将响应中的 `next_page` 原样作为下一次请求的 `page`；`next_page` 为 `null` 表示没有下一页。会话列表不返回 `prev_page`。
- **文件**：支持 `page`、`after_id` 和 `before_id`。`page` 不能与任一 ID 游标同时使用，且后续请求的 `scope_id` 必须与生成该游标时一致。响应包含 `has_more`、`first_id`、`last_id` 和 `next_page`。
- **消息批处理**：使用 `after_id` 或 `before_id` 及响应中的 `has_more`、`first_id`、`last_id`，不返回 `next_page`。
- **模型列表**：当前返回模型目录和 `has_more: false`，不读取分页参数。

以下示例获取智能体的前两页：

```bash
first_page=$(curl -sS --fail-with-body --get "$OMA_BASE_URL/v1/agents" \
  -H "x-api-key: $OMA_API_KEY" --data-urlencode 'limit=20')
printf '%s\n' "$first_page" | jq '.data'
next_page=$(printf '%s\n' "$first_page" | jq -r '.next_page // empty')
if [ -n "$next_page" ]; then
  curl -sS --fail-with-body --get "$OMA_BASE_URL/v1/agents" \
    -H "x-api-key: $OMA_API_KEY" --data-urlencode 'limit=20' \
    --data-urlencode "page=$next_page"
fi
```

游标是不透明的，不要解析或修改。遍历时保持筛选和排序条件一致，并注意数据可能在请求之间变化。无效的已知参数可能返回 `invalid_request_error`；不要依赖服务端拒绝所有未知参数。
